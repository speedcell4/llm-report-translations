1. 先确认你的 GPU 与目标

普通 FP8 可以跨两代受支持硬件使用，但 Hopper 普通 FP8 与 Blackwell 原生 MXFP8/NVFP4 要分开比较。Blackwell 数据中心卡增加了微块缩放相关原生路径，框架、CUDA、算子与布局仍决定能否使用。普通 FP8、DeepSeek 风格 block FP8、MXFP8 是三种不同配方；换卡后的最佳选择与加速比需要重测。H20、GB10、RTX Blackwell 也不能套用 B200 的支持结论。先运行 nvidia-smi，并用 PyTorch 查询 torch.cuda.get_device_capability()。查看硬件差异、性能数据与支持边界。

2. 选一条最短上手路线

  • 先跑通服务：使用 vLLM 加载官方量化 checkpoint，先保持 KV 默认精度；确认结果后单独尝试 FP8 KV。安装、服务与请求示例。

1. 先建立坐标：低精度究竟降低了什么

低精度不是一个开关，而是在一条计算链上分别决定哪些信息可以少存、少搬、少算。看到“FP8 模型”，第一反应应是问：它是下载文件里的 weight 为 FP8，还是矩阵乘法的 weight 与 activation 都为 FP8？前向如此，反向也如此吗？乘法低精度之后，用什么累加？gradient 是按什么精度跨 micro-batch 累积、跨 GPU 归约？优化器更新的参数又保留多少位？如果没有回答这些问题，同一个标签可能对应完全不同的成本和误差。

本文把 W 定义为 weight，把 A 定义为前向 activation，把 G 细分为 activation gradient 和 weight gradient，把 KV cache 单列为自回归生成的持久状态。它们不构成彼此独立的四个存储桶：K、V 本来也是 activation；训练中的 activation checkpoint 是为了反向传播保存的中间量，推理中的 KV cache 是为了避免重复计算历史 token。训练通常需要前者，生成通常需要后者。RL 的 rollout 同时属于训练系统的一部分和一次推理工作负载，因此也会用到 KV cache。

1.1 三个收益，三种不同的瓶颈

第一是容量收益：同样多元素用更少字节存储，模型或更长上下文才能装进显存。第二是带宽收益：从 HBM 读取、在 GPU 之间传输的数据减少，才能缓解 memory-bound 或 communication-bound 路径。第三是算力收益：硬件原生执行低精度乘法，提高 compute-bound GEMM 的吞吐量。weight-only INT4 可能主要赚前两项，在计算前把 weight 转成 FP16/BF16；原生 FP8 GEMM 则有机会同时赚第三项。反量化、scale reduction、布局转换、转置副本会消耗一部分收益，因此必须看端到端的时间和峰值显存。

以一个不含分片的理想化 AdamW 例子说明：每参数如果有 BF16 计算权重 2 字节、FP32 master 4 字节、FP32 gradient 4 字节、FP32 两个 moments 共 8 字节，合计是 18 字节。若 gradient 只存 BF16，则变成 16 字节。这只是分项算账，不是所有框架的固定占用；有的实现把 FP32 参数本身作为 master，不额外保存 BF16 常驻副本，有的在 optimizer step 时才临时物化参数。把 GEMM 的瞬时权重变成 FP8 并不自动把整个 18 字节变成 1 字节；ZeRO/FSDP 通过分片减少每卡份额，与低精度是另一个维度。

1.2 训练比推理多了一条会积累误差的闭环

推理中的量化误差主要影响这次输出；训练中的误差会改变 gradient，再改变下一步 weight，继而改变后续所有样本的计算分布。一个短测中很小的系统性偏差，可能在数十万次更新后改变收敛结果。随机、无偏、幅度可控的误差与固定方向的舍入偏差不能等同。因此，训练 recipe 往往让大 GEMM 使用低精度，把长时间累积的信息保留在更高精度中。早期混合精度训练就已经把低精度计算、副本权重和高精度更新分开设计。来源：Mixed Precision Training。

2.1 指数解决“够不够大”，尾数解决“分得够不够细”

对规格化二进制浮点数，可以用 \(x=(-1)^s(1+f)2^e\) 理解：符号位决定正负，指数移动量尺，尾数决定同一个数量级里有多少刻度。指数更多，能跨越更宽数量级；尾数更多，相邻值更密。把所有值乘一个 scale，能把量尺移到合适的位置，却不会凭空增加尾数位。BF16 可能既没有上溢，也把两个接近的数舍入成同一个值；FP16 可能保留更多小数，却在遇到较大 activation 时变成 Inf。这是两个不同问题。

2.2 INT、FP、NF4 的量尺不同

对称 INT8 可以写成 \(q=\operatorname{clip}(\operatorname{round}(x/s),-127,127)\)，恢复值为 \(\hat{x}=sq\)。在同一组内，相邻恢复值的间距固定是 \(s\)。浮点量化则把 \(x/s\) 舍入到一个浮点集合上，随着数值变大，刻度也随数量级增大。INT 格式善于把有限区间均匀切分；FP 格式适合跨多个数量级的分布。两者都可能受 outlier 影响，差别是误差怎样分布。非对称 INT 还会引入 zero-point，用有限编码更好地覆盖偏移分布，但增加内核处理项。

NF4 则是一个针对特定分布设计的 4 位非均匀码本，不能看到“4 bit”就把它等同于 FP4 E2M1。相同位宽下，码本、scale 粒度、是否训练时考虑量化、是否有硬件直接乘法支持，决定了完全不同的行为。低比特存储格式与硬件运算格式可以不相同：解码一个码本再做 BF16 GEMM，在系统上是成立的，但不代表获得原生 FP4 Tensor Core 吞吐。

TF32 则需要放在不同坐标里：它通常指 Tensor Core 的乘法输入精度模式，输入/输出张量仍可保留 FP32 存储；不能按“19 位”直接计算显存节省。矩阵乘法的 reduced-precision reduction、TF32 开关以及完整 FP32 累加也不是同一个开关。排查 BF16/FP16 与 FP32 的差异时，应记录这些模式，避免参考路径本身也悄悄换了一种乘法。来源：PyTorch 数值精度说明。

2.4 FP4 的数值例子：scale 再准确，也只有少数格点

E2M1 非负有限值的集合可以列成 0、0.5、1、1.5、2、3、4、6，负值按符号对称。设一个 block 的最大值是 12，选择恢复 scale 为 2，则可表示的非负恢复值是 0、1、2、3、4、6、8、12。现在 7 通常会舍到 6 或 8，5 会舍到 4 或 6，0.2 会舍到 0。即使最大值完全没有 clipping，主体值也可能产生明显误差。这正是不能只用“有没有覆盖 amax”判断 FP4 质量的原因；原始数据落在哪些格点之间，与最终函数对这些位置的敏感性同样重要。

再看共享 scale 的约束。假设两个 block 的最大值分别是 12 和 0.12，若给两组分别选 2 和 0.02，可以让相同编码集合分别覆盖两种数量级；若它们共用 2，小组里的 0.12 附近元素就可能全部消失。NVFP4 的 block scale 自己又要量化为 E4M3，因此目标 0.02 未必能精确表示；tensor 级 global scale 的作用之一，是把这些 block scale 放进适合它们的表示范围。两级缩放把范围分配问题拆开了，仍然没有消除元素编码和 scale 编码各自的舍入误差。以上是格式机制推导，不是某个真实模型的误差测量。

3.2 为什么 master weights 常常比计算权重高精度

SGD 的最简单更新为 \(w_{t+1}=w_t-\eta g_t\)。若 \(\eta g_t\) 远小于当前 \(w_t\) 附近的量化间距，那么每次单独舍入都会让更新消失。例如 BF16 weight 为 1，每步理论上增加 0.001；若每步都在 BF16 参数上直接加并舍入，多次操作可能永远停在 1。若在 FP32 master 上累积，四步后的真实值约 1.004，再生成 BF16 副本时就可能跨过下一个舍入边界。计算副本可以连续数步相同，master 内部仍然在学习。

master 不一定是额外的完整常驻副本。在常见 PyTorch autocast 路径里，模型参数可以一直是 FP32，只在算子入口选择 BF16/FP16 计算；这个 FP32 参数本身承担高精度更新职责。有的分布式训练框架把低精度模型参数与分片的 FP32 master 分开保存。必须读实际 optimizer 与混合精度策略，不能看到 autocast(dtype=torch.bfloat16) 就断言参数、gradient、Adam moments 都是 BF16。来源：Transformer Engine 低精度训练基础。

3.3 Adam 的 moments 为什么也是精度预算的重要部分

Adam 用一阶矩 \(m_t=\beta_1m_{t-1}+(1-\beta_1)g_t\) 和二阶矩 \(v_t=\beta_2v_{t-1}+(1-\beta_2)g_t^2\) 形成更新方向，典型更新含 \(\hat m_t/(\sqrt{\hat v_t}+\epsilon)\)。一阶矩有符号，二阶矩非负，分布和敏感性不同。二阶矩对很小 gradient 先平方，数量级会进一步下降；若把 \(v_t\) 粗糙舍入成零，分母可能被 \(\epsilon\) 主导，改变实际步长。若 \(\epsilon\) 本身又在某个低精度算术中下溢，风险会叠加。因此“moments 用低精度保存”与“所有 optimizer 算术都低精度完成”必须区别。

一种合理的实现可以是：低比特保存 moments，需要更新时解码到高精度寄存器、计算更新、重新量化保存。它节省长期状态的容量与读写，但并不要求在最小 dtype 上执行除法与开平方。block-wise optimizer quantization 的价值正是按块适应状态分布；其成功不能直接推出把所有 optimizer 张量强制 cast 成 INT8 也会成功。来源：8-bit Optimizers via Block-wise Quantization。

本仓库 DeepSeek-V3 已有一个具体的“混合得很细”的例子：Linear 的三类 GEMM 接受 FP8 输入，而 master weights 与用于 batch 累积的 weight gradient 保留 FP32，AdamW 两个 moments 保存为 BF16。更完整的公司级配方见后文对照；这里只用它说明，算力、存储与更新的精度可以独立选取。仓库译文：第 15 页、第 18 页。

3.4 低精度预训练、QAT、低比特微调不是同一项实验

原生低精度预训练关注从训练早期到训练末期，大部分计算是否能保持目标数值行为。QAT 在训练时让模型感受到量化误差，可能采用假量化：先量化再恢复成高精度张量来模拟部署误差，底层计算仍未必是目标低精度硬件内核。低比特 adapter 微调还可以冻结压缩后的基础模型，仅更新少量高精度参数；这时基础 weight 没有全量 optimizer 状态，但要继续反传 activation gradient 才能训练前面的 adapter。三种路径的显存、数值挑战和速度不能混为一谈。

对于量化后再恢复的 weight，\(\hat W=Q(W)\)，真实的离散舍入函数几乎处处导数为零。训练系统常用代理 gradient 或自定义 backward 让优化继续进行，但代理规则也是 recipe 的组成部分。训练时模拟的 clipping、scale 与部署时实际编码若不同，会产生“QAT 指标很好、导出后掉点”的落差。因此验证对象应包含导出的最终文件与实际执行内核，而不只看训练过程中浮点图的 loss。

3.5 不要把“有 gradient”误认为“所有 weight 都在更新”

冻结基础 weight 的 adapter 微调中，Dgrad 仍可能存在，因为信号需要流向更浅位置的可训练模块；基础 weight 的 Wgrad 和 optimizer state 却可以不分配。全量微调则需要这些状态。由此可见，同样是使用 4 位基础模型，adapter 方案的显存节省不能外推到全量 FP4 训练。反过来，支持低精度 Wgrad 的预训练系统，也不一定提供方便的低比特 checkpoint 导出与服务部署。比较方案时必须列出可训练参数集合，而不只写模型总参数量。

参数统计也要排除另一个误会：MoE 的“每 token 激活参数少”减少当次计算，却不代表未被该 token 选中的所有专家都无需 optimizer 状态。不同专家会在不同 token 和不同 batch 中更新，完整训练系统仍要保存或分片它们的训练状态。对大型 MoE，压缩 moments、分片 master、降低 all-to-all 流量可能比继续压缩单次 GEMM 的少量缓冲区更影响每卡容量；具体主导项应按实际参数量与激活缓存量计算。

4. 训练中的 activation：分组、scale 与保存方式

4.1 先统一 scale 的定义，避免公式看起来相反

本文统一令 \(s\) 为反量化 scale，即 \(q=Q(x/s)\)，恢复为 \(\hat x=sq\)。若一组最大绝对值为 \(a\)，编码最大有限值为 \(q_{\max}\)，最简单的 max-based 规则是 \(s=a/q_{\max}\)。一些实现把它的倒数命名为 scale，即先乘 \(q_{\max}/a\)，同时把本文的 \(s\) 叫 scale inverse。看到公式相反时先核对方向，不要误判为算法不同。全零组还需要明确约定非零 scale，避免除零；实际内核通常会处理这个边界。

以对称 INT8 的教学例子：一组数为 0.05、0.10、0.15、12.7，按最大值选 \(s=0.1\)，三个普通值只能映射到很粗的整数格点附近；其中 0.05 落在两个编码的中点，结果还取决于 tie-breaking。如果把最后一个 outlier 单独成组，前三个数按 0.15 选 scale，普通值的刻度就从 0.1 缩小到约 0.00118。关键不是把 12.7 从模型里抹掉，而是不让它独占整组的量尺。对 FP8，刻度不均匀，但“一个极端值迫使整组共用较大量尺”的机制仍然存在。

4.3 current scaling 与 delayed scaling：准确性和额外扫描的取舍

current scaling 先测当前张量或当前 block 的 \(a_{\max}\)，再选 scale，因此能立即响应本步突发 outlier。代价是 reduction、读写和同步；若未融合，可能先生成高精度输出、扫描极值、再量化，导致额外 HBM 往返。delayed scaling 根据此前若干次的极值历史预测本次 scale，当前计算顺便记录新极值，为下一步做准备。它更容易和高吞吐 kernel 结合，但分布突然变化时预测会过小或过大。Transformer Engine 当前提供两类方案和 block recipe，选择不能只看名字中的位宽。来源：Transformer Engine FP8/FP4 使用指南。

举一个变化场景：过去十步最大值在 2 附近，本步出现 20；若本步仍用按 2 选的 scale，20 会饱和。加 margin 能预留范围，但同时让普通值使用更少有效刻度；长时间保留历史最大值能保护偶发大值，却也可能在异常消失后继续牺牲分辨率。scale 的更新窗口、是否取历史 max、power-of-two 约束、margin 和分布式同步，都是可改变结果的超参数。记录 amax 的同时还应记录饱和比例与近零比例，因为“最大值被覆盖”不代表主体分布得到良好表示。

4.4 为什么 GEMM 的 scale 沿归约轴变化会影响实现

若两个矩阵各只有一个 scale，\(X\approx s_XQ_X\)、\(W\approx s_WQ_W\)，就有 \(Y\approx s_Xs_W(Q_XQ_W^\top)\)，可先完成低精度乘法，再统一恢复尺度。若沿 \(K\) 切成多个 group，公式变为 \(Y\approx\sum_g s_{X,g}s_{W,g}(Q_{X,g}Q_{W,g}^\top)\)。不同部分和必须按自己的 scale 恢复再相加，不能把所有整数或浮点编码的部分和直接合在一起，最后只乘一个 scale。硬件 microscaling 的重要性正是让这种局部 scale 更接近乘加执行路径。

4.5 保存 activation 与计算 activation 需要分别决策

前向计算结束后，backward 不一定需要保存全部输出，但往往要保留 Linear 输入、非线性输入或归一化统计量。保存为 FP8 可以减少显存；保存后再恢复不会消除量化误差。另一种选择是 checkpointing：只保留部分高精度边界，反向时重算内部 activation，用算力换容量。还可以两者结合，不过重算时的随机数、dropout、scale 历史必须与框架的 checkpoint 机制兼容，否则重算不再是原来的前向。仅用“activation 是 FP8”无法判断这里具体省了多少。

一些 activation 同时被多个 backward 分支使用：对 Linear 足够的精度，未必对 attention backward 也足够。本仓库 DeepSeek-V3 特别为 attention 后 Linear 的输入缓存使用定制 E5M6，并对部分 SwiGLU 输入采用低精度缓存、反向重算输出。该细节说明缓存格式可以是训练系统内部格式，不等同于公开的模型权重格式。仓库译文：第 18 页。

5. gradient：动态范围、累积误差与低精度 backward

5.1 activation gradient 与 weight gradient 承担不同职责

activation gradient 是沿层传播的误差信号，形状通常类似 activation；weight gradient 是汇集许多 token 对某个参数的贡献，形状类似 weight。二者的分布、归约轴和生命周期都不同。activation gradient 中，某几个 token 可能异常大；weight gradient 中，许多正负贡献可能相互抵消。对前者，粗粒度 scale 容易抹掉普通 token 的信号；对后者，高精度累加有助于保留小贡献与抵消后的结果。把两个都记作 G8，会隐藏核心风险。

再区分三种“累积”：GEMM 内部把许多乘积相加；多个 micro-batch 把 weight gradient 相加；多个 DP rank 把 gradient 归约。第一种可能发生在 Tensor Core 或寄存器，第二种发生在参数对应的 gradient buffer，第三种还涉及网络传输与 collective 算术。三者中任何一个低精度都可能引入误差。使用 FP32 gradient buffer 不能修复前面的乘积输入已经量化成零；使用 FP32 GEMM 输出也不能证明整个内部 reduction 都具有完整 FP32 精度。

5.2 loss scaling 保护的是数值范围，不是额外有效位

把 loss 变成 \(L'=SL\)，按链式法则得到 \(g'=Sg\)。若 backward 中的小 gradient 原本会低于 FP16 可表示范围，适当的 \(S\) 能让它存活，optimizer step 前再计算 \(g=g'/S\)。例如原本 \(g=10^{-8}\)，取 \(S=1024\)，scaled gradient 约为 \(1.024\times10^{-5}\)，更有机会在 FP16 中保留。这个过程不能拯救缩放前就发生的前向上溢，也不能为同一个张量里相差过大的值无限扩展范围。

动态 loss scaler 会在检测到非有限 gradient 时减少 scale 并跳过更新，连续一段安全步骤后再尝试增加。必须在 clipping 前 unscale，否则等于把 clipping 阈值也乘错；也不应每个 micro-batch 都更新 scale，否则同一个累积 buffer 中混入不同缩放倍数，最后无法用一个除法还原。FP16 的经典处理流程是这一机制，而 BF16 因指数范围宽，通常无需相同的 gradient scaling；但 BF16 仍然有尾数舍入与训练发散问题。来源：NVIDIA 混合精度训练指南。

FP8 则通常需要每张量乃至每组独立 scale：一个全局 loss scale 只能整体移动所有反向信号，不能同时适配层间差异、token 差异与前向 weight/activation 的差异。把 FP16 AMP 的 scaler 原封不动搬到 FP8，不会自动得到完整 FP8 recipe。

5.3 为什么反向格式有时用 E5M2，有时又全用 E4M3

E5M2 牺牲一位尾数换更宽指数范围，适合范围难预测的 gradient；E4M3 有更多局部刻度，却更依赖 scale 的精细适配。这不是“谁更先进”的线性替代关系。若只按整张量缩放，极宽动态范围可能逼迫使用 E5M2；若把幅度差异较大的值拆到不同小组，可以重新把位预算投入尾数。对某个 recipe 成功的全 E4M3，不应把它单独摘出来使用，丢掉其细粒度 scaling、累加策略与高精度例外。

5.4 梯度累积应按真正的 loss 分母算

设一个有效 batch 由 \(n\) 个等大小 micro-batch 组成，每个 micro-batch 的 loss 都是相同数量样本的平均值，那么可在 backward 前把每个 loss 除以 \(n\)，再累积 gradient。如果每个 micro-batch 的有效 token 数不同，例如动态长度、padding 或不同数量的 masked token，这种简单平均可能改变训练目标。此时应按有效 token 数构造总分子与总分母，并考虑 DP rank 的归约方式。错误的归一化可能表现为“换精度之后才爆炸”，实际原因却是为了省显存改变了 batch 结构。

gradient clipping 也应看完整有效 batch 的 unscaled gradient norm，而不是每个 micro-batch 先裁一次再相加：后者是不同的优化算法。分布式分片参数时，norm 还要跨对应分片聚合，不能只对本卡小片参数使用普通 norm 就声称获得了全模型阈值。低精度调试需要把这些训练语义固定，否则数值比较没有可解释性。来源：PyTorch AMP examples。

5.5 stochastic rounding 为什么在 FP4 更重要

若实数 \(x\) 位于两个可表示数 \(a<x<b\) 之间，最近舍入总是向较近的一端；对小更新，可能连续许多步都舍到同一点。随机舍入令 \(P(\hat x=b)=(x-a)/(b-a)\)，其余概率舍到 \(a\)，于是理想条件下 \(\mathbb{E}[\hat x]=x\)。这不能让单次舍入更准，但可避免固定方向的量化偏差。以 FP4 在 1 与 1.5 之间表示 1.1 为例，可用 20% 概率取 1.5、80% 取 1，期望仍为 1.1；每次取 1 的最近舍入则总少 0.1。

无偏不等于无噪声：上例有相当明显的单次方差，训练能否容忍要靠规模与收敛验证。随机舍入也不能救回先被 clipping 掉的 outlier；真实系统还涉及有限随机数、scale 误差和相关性。因此它通常与细粒度 scaling、敏感层高精度以及分布变换一起使用。NVFP4 训练方法把 stochastic rounding 用于低精度 gradient，是这组联合措施之一。来源：Pretraining Large Language Models with NVFP4。

5.6 通信压缩还要问“接收端怎样加起来”

将一份张量压成 FP8 发给另一张卡，与把许多张卡的 FP8 gradient 直接相加，是不同问题。点对点或 all-gather 主要搬运编码和各自 scale，接收端可以解码后使用；all-reduce 则需要把多份数值放到同一量纲里做求和。如果每个 rank 各自量化后直接按编码相加，scale 不同就没有数值意义。即使统一 scale，也可能因不同 rank 的极值差异牺牲精度。因而需要检查 collective 是否原生支持该格式、scale 如何同步、归约在哪种 dtype 完成，以及是否采用额外误差补偿。

同样，MoE dispatch 只是把 token 送到专家，combine 则要把多个专家的输出按路由权重合并；两者对数值精度和动态范围的要求可以不同。把 dispatch 压缩成功，不说明 combine 也能用同样精度安全累加。容量、通信和算子三处都写“FP8”仍不足以复现实验，必须画出 scale 与量化边界在哪里产生、在哪里恢复、在哪里求和。

6. 推理中的 weight：先把模型装下，再决定怎样算得快

推理时没有常规反向传播所需的 gradient 与 optimizer state，最先面对的是权重、运行时 activation、KV cache 和 kernel 工作区。Weight-only 方案主要压缩第一项；它不自动缩小所有 activation，也不自动改变 KV cache。W4A16 通常表示权重以约 4 bit 的量化表示保存，输入 activation 保持 FP16/BF16。实际 kernel 可以在读入过程中拆包、反量化并送入较高精度运算；因此不能仅凭 checkpoint 写着 INT4，就认定 Tensor Core 做的是 INT4×INT4。Marlin 是这类存储与计算协同设计的重要实例。来源：Marlin

如何建立一份可比较的精度配置

对每个模型，应把“原始权重、磁盘压缩格式、设备权重布局、activation 量化方式、GEMM 乘数、累加、输出、KV cache”分别记录。假如只知道“4 bit”，还缺少 group size、scale 的 dtype、zero-point、对称性、被排除层以及打包格式。两份同为 W4A16 的模型，可能使用不同校准方法，也可能根本不能由同一个 loader 读取；量化算法名称、checkpoint 格式和执行 kernel 是三个不同层面。vLLM 把多个量化后端分开列出，正说明这些区别会影响部署。来源：vLLM 量化后端

显存估算也应从格式而不是名称开始。若一组 G 个权重各 b bit，另保存一个 s bit 的 scale 与一个 z bit 的 zero-point，则忽略对齐后的平均成本为 \(b+(s+z)/G\) bit/weight。group 越小，局部动态范围越容易表示，但元数据、索引与访存负担上升。敏感层保持 BF16、embedding 与输出层未量化，以及运行时重排或临时副本，都会使整个模型的平均 bit 数高于主体权重的名义位宽。这是预算公式；不能直接当成某个实现的实际峰值显存。

RTN：所有复杂方法都需要比较的基线

Round-to-nearest 的基本步骤是选定范围、计算 scale、将权重映射到最近可表示数。它不根据下一层输出误差补偿，因此容易把“权重逐元素误差小”误当成“模型误差小”。在一层线性运算中，真正关心的是 \(XW\) 与 \(X\widehat W\) 的差；输入分布使某些方向比另一些方向重要。RTN 的价值在于建立低成本、可复现的下限：先确认仅改变格式会造成多大质量变化，再判断 GPTQ、AWQ 或旋转带来的额外复杂度是否值得。GPTQ 的问题定义正是把校准输入下的层输出重建作为目标。来源：GPTQ

GPTQ：量化一个权重后，把误差分配给尚未量化的权重

GPTQ 借助校准 activation 的近似二阶信息判断误差代价，在逐步量化时更新其余权重以补偿已经引入的误差。这里的“二阶”围绕层重建问题，不表示对整个模型执行一次完整 Hessian 求逆。分块处理让代价可控；实现中的 act-order 按 activation 重要性安排量化顺序，true-sequential 则更严格地模拟前面已量化算子给后面算子带来的输入变化。来源：GPTQ 官方实现

它适合已有可用 FP16/BF16 模型、愿意准备代表性校准集、希望把主体权重压到 3–4 bit 的场景。风险集中在校准覆盖不足、层间误差累积和极低位宽：代码、数学、多语言或长上下文数据若与校准集差别很大，局部重建最优不保证任务最优。实际选型应比较同一个模型、同一格式与同一 group size 下的 RTN/GPTQ，随后再比较不同格式；否则算法提升和格式差异会混在一起。

AWQ：activation 感知不等于把 activation 也压到 4 bit

AWQ 通过 activation 统计识别重要的权重通道，并用等价缩放减少这些通道的量化损伤。重要性不是简单按权重绝对值排序；某个权重方向遇到大的 activation 时，对输出更敏感。实现把保护机制编码为缩放与量化参数，避免为少数重要权重建立昂贵的不规则高精度旁路。AWQ 的典型部署仍是 weight-only，名称中的 activation-aware 描述的是校准依据。来源：AWQ

应区分“重要通道”与“outlier 通道”：前者由输出误差敏感度定义，后者通常由分布尾部定义，两者可能重合，但不是同义词。AWQ 与 SmoothQuant 都利用线性运算的等价缩放，然而 AWQ 的主要目标是保护低 bit 权重；SmoothQuant 的主要目标是使 activation 更容易进入 W8A8。把二者归为“都把 activation 变小”会丢失优化目标。选择 AWQ 时还要检查导出格式与运行时是否匹配，不能把任意以 AWQ 命名的目录强制交给某个 kernel。

QuIP#、非均匀码本与更低位宽

QuIP# 把随机 Hadamard 变换带来的 incoherence 与 E8 lattice 向量码本结合，使原来高度不均匀的权重方向更适合统一压缩，并可用微调恢复质量。它不是“把 INT4 改成另一个整数范围”这么简单，而是改变表示空间与多个数共同编码的方式。向量码本可能改善单位 bit 的重建质量，同时引入查表、编码、布局与专用 kernel 的要求。来源：QuIP#

对于 2–3 bit，应把研究质量与部署成本一起评价：码本和 scale 也占内存；高精度例外可能破坏连续访存；恢复训练也需要数据与算力。如果目标是单卡装下更大模型，极低位宽可能值得；如果模型本来已经能装下，而服务瓶颈在长上下文 attention，更激进的权重压缩可能并不改善延迟。这是由瓶颈推导出的工程判断，必须用实际 workload 验证。

把量化误差沿着线性层算一遍

设量化后的权重与输入为 \(\widehat W=W+E_W\)、\(\widehat X=X+E_X\)，则输出误差是 \(\widehat X\widehat W-XW=XE_W+E_XW+E_XE_W\)。这说明只测 weight 的逐元素 MSE 不够：同样的权重误差遇到不同输入方向，会产生不同输出误差；同时量化 W 与 A 时，还出现二者共同作用的误差项。因此 AWQ 使用 activation 信息、GPTQ 使用校准输入重建输出，都是在处理“量化误差被模型放大多少”的问题。

对于对称均匀量化，若范围为 \([-a,a]\)，步长大致随 \(a/(2^{b-1}-1)\) 增大。把一个极端值纳入 a 会让所有普通数值承担更大的步长；裁剪则把部分误差集中到尾部。两种选择都不是无损操作。判断 clipping 是否合理，要比较经过该层后误差如何变化，而不是仅看分布图变得更好看。偏移量、非对称量化与非均匀码本会改变具体公式，但“表示预算如何分配”的矛盾仍在。

量化参数的轴也必须画清。在线性层权重矩阵按输出通道还是输入通道分组，会改变 scale 与 GEMM 归约的关系。模型文件可能以转置形式存储权重；代码中 axis=0 未必就是论文图里的输入通道。正确核查方法是同时写出张量 shape、实际 stride、分组轴与 scale shape，并用一小块数据验证量化再反量化结果。只从变量名推断通道含义，很容易得到能加载但数值错误的模型。

MoE：总体压缩率与每个 token 的计算量要分别看

MoE 的专家权重可以占据绝大多数参数，因此只量化专家往往就能显著压缩磁盘与显存；但每个 token 只激活部分专家，单 token FLOPs 并不按总参数量计算。router、共享专家、attention 和输出层的精度例外也有不同作用。Repo 已翻译的 gpt-oss 报告明确说后训练期间将 MoE 权重量化为 MXFP4，不能把这句话展开为所有模块、activation 与 KV 都采用 MXFP4。仓库来源：gpt-oss 量化部分

Grouped GEMM 中一个专家每轮拿到多少 token，直接影响低精度算术能否摊薄量化开销。总 batch 相同，但路由分布不同，专家的局部 shape 也不同。校准应覆盖稀少专家；压测应记录路由与并行方式；kernel 选择需要对 MoE 单独确认。不能用 dense Linear 的单层 benchmark 替代 MoE 服务结果，也不能因为非活跃专家不计算就忽略它们占用的常驻显存。

7. 推理中的 activation：outlier 决定能否真正使用低精度 GEMM

Weight 的分布在部署前已经固定，activation 却随 token、位置、样本、模式与层改变。一个大 activation 会扩大整个量化组的范围，使普通数值的有效分辨率下降。即使整数格式不溢出，只要大部分数被挤到相同几个量化格，仍会严重损失信息。FP8 有指数位，能缓解范围问题，却不会消除有效位数有限、scale 估计不准和某些方向特别敏感的问题。LLM.int8 的观察说明，少数系统性大特征会对大模型量化产生不成比例的影响。来源：LLM.int8

分清三种 outlier

一种是稳定地出现在特定 channel 的结构性大值，一种是某些 token 才出现的样本性大值，另一种是少数 token 的少数通道中出现极大数值的 massive activation；这些描述轴并不互斥。per-channel 统计能处理第一种的尺度差异，per-token 统计对第二种更直接，而第三种可能使包含这些极值的量化组受到影响。实际模型还可能在 gated MLP 的中间 activation、attention 投影、残差流中形成不同分布。完整报告中的厂商配方必须注明作用对象，不能把“控制 residual stream”与“控制 GEMM 输入”写成同一个步骤。

LLM.int8：把重要的大值保留在高精度旁路

其思路是把异常特征维度从主体 INT8 运算分离，在较高精度矩阵乘中计算，再与主体结果相加。这样保留关键特征，而普通部分仍享受低精度表示。代价是检测、拆分、额外 GEMM 与结果融合；因此“显存减半”不等于“端到端速度翻倍”。当 outlier 比例或输入形状不利时，旁路开销会抵消收益。对 threshold 的调整必须同时观察质量与延迟。来源：Transformers bitsandbytes 文档

SmoothQuant：等价迁移，不是删除 outlier

对于 \(Y=XW\)，可取一个对角缩放矩阵 \(S\)，使 \(Y=(XS^{-1})(SW)\)。全精度下结果相同；量化时把 activation 的难点部分迁移到相对容易处理的 weight。缩放不能无限增大，否则 weight 的量化误差会恶化，因而需要平衡系数和校准统计。离线融合到相邻线性层或归一化参数可以减少在线成本，但前提是图结构确实允许。来源：SmoothQuant

这一技巧最重要的边界是：代数等价只保证量化前的函数不变，不保证量化后的误差不变；单一路径可融合的变换，在共享输入、多分支或特殊 attention 结构中也不一定能直接照搬。对 MoE，还要考虑不同专家收到的 token 分布：只有极少校准 token 激活的专家，其范围统计可能不可靠。因此应记录每个专家的覆盖率，避免只报告全模型平均误差。

OmniQuant：让 clipping 与等价变换接受校准优化

OmniQuant 把 weight clipping 和等价变换参数设为可学习量，通过 block 级重建误差进行校准。它把人工选范围的一部分工作交给优化过程，同时保持 PTQ 路线；它不是从头训练低精度基础模型。所谓 learnable 并不意味着应让所有原始权重无约束更新。需要分别记录参与优化的参数、校准样本、训练步数与被导出的推理参数。来源：OmniQuant

QuaRot 与 SpinQuant：换坐标系，分散 outlier

正交旋转能够在保持内积等关系的同时，把能量集中在少数维度的向量分散到更多维度。QuaRot 利用 transformer 中可保持计算等价的变换，并结合快速 Hadamard 旋转覆盖权重、activation 与 KV；SpinQuant 进一步学习旋转以降低量化误差。二者共同说明，量化困难不仅取决于数值位宽，还取决于用什么坐标系表示张量。来源：QuaRot；SpinQuant

旋转不是可以随意插入任何位置的无害操作。非线性函数通常不与任意旋转交换；RMSNorm、残差、head 划分、RoPE 和 gated MLP 等结构对可融合变换有约束。某些旋转能预先并入权重，另一些需要在线执行；前者主要增加导出复杂度，后者还增加每次推理成本。论文中的“4 bit end-to-end”应按论文列出的矩阵乘与张量理解，不能扩张成 softmax、归一化、残差累加和全部临时结果都以 4 bit 完成。

outlier、attention sink 与 residual sink 不是同义词

量化视角下，outlier 描述超出主体分布的大数；attention sink 描述某些 token 持续吸收 attention；residual sink 则与残差流特定维度的大激活有关。它们可能关联，却分别涉及数值分布、注意力分配与表示结构。特别是 attention 分数大，不代表最终对输出贡献大；归一化和后续 value 投影还会改变效果。仓库的相关译文强调 outlier 与归一化共同承担重缩放功能，直接裁掉可能损害模型。仓库来源：attention 与 residual sinks

因此低精度有两类路线：部署时在既有函数附近进行缩放、旋转与量化；训练时改变归一化、门控或架构，让模型学会避免过度依赖极大值。后一类往往需要重新训练或恢复训练，不能把改过结构的质量提升归因于一个纯 PTQ 算法。对已有 checkpoint，先使用可保持全精度函数等价的变换更容易做可控比较；但等价变换在低精度下仍需评估误差。

FP8 与 INT8：不是浮点必然比整数好

INT8 在固定范围内提供均匀格点，若动态范围已由 scale 和分组处理好，主体数值可能得到较高绝对分辨率。FP8 提供随指数变化的相对分辨率，覆盖范围更灵活，但相同量级的有效尾数位较少。应该同时考虑数据分布、scale 粒度、校准方法和 kernel。比较一个精细 per-channel INT8 与粗 per-tensor FP8，得到的结果不能直接解释为两种标量格式的胜负。

E4M3 与 E5M2 也应按对象选择。更大的指数范围可以降低溢出风险，较少尾数又会增加舍入误差；选 E5M2 并不等于更安全地保留全部信息。推理常见的 FP8 weight/activation 路径多采用 E4M3，但某条 KV 或训练反向路径可能不同。报告应写出具体 format，而不是把所有 8 bit 浮点都压缩成同一个 FP8 标签。所有关于“无需校准”的描述也要附上限定：通常是当前 recipe 的权重 RTN 与动态 activation，不涵盖任意模型与所有算子。

8. KV cache：把“模型压缩”推进到长上下文状态压缩

标准自回归 attention 为每一层、每个历史 token 保存 key 与 value，避免每生成一个新 token 都重新计算前缀。忽略分页、对齐、共享与特殊架构时，cache 大小约为 \(2BLTH_{kv}d_hb\) 字节：B 为请求数，L 为层数，T 为缓存长度，\(H_{kv}\) 为 KV head 数，\(d_h\) 为 head 维度，b 为每个缓存元素的字节数。GQA/MQA 改变 KV head 数，MLA 改变缓存表示；这些是架构压缩，与把同一个 cache 从 BF16 变成 FP8 是不同维度，收益不能重复计算。

为什么 key 与 value 需要不同量化轴

Key 参与 \(QK^T\) 决定 attention 分数，Value 参与加权求和。二者的分布、异常维度结构、误差传播路径不同。KIVI 观察到 key 更适合 per-channel，value 更适合 per-token，提出不需微调的非对称 2 bit KV 量化，并保留一段较高精度 residual cache 以适应流式写入。不要把论文的 per-channel K 改写为“整个运行时永远能按一个固定 channel scale 即时写入”；分组聚合与尾部处理也是算法的一部分。来源：KIVI

从误差传播看，Key 的扰动先经过分数与 softmax，可能把注意力移到另一个 token；Value 的扰动则在既定 attention 权重下影响输出。不能据此普遍断定“K 总比 V 敏感”或固定使用 K8V4：实际敏感性与模型、层、head、上下文和任务相关。合理的实验矩阵应至少把只量化 K、只量化 V、同时量化三种情况分开，再测长上下文检索与完整生成。

KVQuant：RoPE 位置、码本与 outlier 分离

KVQuant 将 per-channel Key、pre-RoPE Key 量化、敏感度加权非均匀码本与逐向量 dense-and-sparse 处理结合。Pre-RoPE 的作用是利用旋转前更有利的分布结构；它需要相应存储与 attention 执行路径配合，不是把常规 post-RoPE cache 的 dtype 字符串改掉即可。把少量 outlier 另存也要算索引和合并代价。来源：KVQuant

更一般地，cache 量化应交代四件事：何时量化、沿哪个轴成组、何时重新计算 scale、读出后在哪里恢复。Prefill 可以一次处理一段连续 token，decoding 通常逐 token 追加；原本为批量压缩设计的组，如果每生成一个 token 都重压历史数据，可能把节省的带宽换成额外工作。分页 cache 还会引入 block 边界和请求共享关系，算法中的 group 与系统中的 page 不一定相同。

FP8 KV：存储 dtype 与 attention dtype 分别设置

vLLM v0.31.0 的 KV 文档区分 per-tensor 与 per-attention-head scale，后者要求指定 attention 后端和 llm-compressor 校准路径。它也明确指出，当采用支持的 Flash Attention 3 FP8 路径时，Q 会一并量化，QK 与 ScoreV 可在 FP8 域计算。其他组合可能是 FP8 存储、读取时反量化；因此“KV FP8”本身无法证明整个 attention 采用 FP8。来源：vLLM v0.31.0 KV cache

对同一个 FP8 cache，默认 scale=1 与使用真实数据校准 scale 是不同数值方案。E4M3 的范围不是无限的；若尺度与输入不匹配，仍会饱和或损失大量有效精度。vLLM v0.31.0 已移除旧的 --calculate-kv-scales 路径，不应照旧博客使用启动时随机 token 估计；当前主流程采用离线数据集校准并加载 scale。校准数据集、scale 粒度与实际 attention 后端都应进入实验记录。

FP4 cache、旋转与更新的系统路径

SGLang 的官方源码文档把 FP8 scale 的 checkpoint/JSON 路径与 FP4 分块动态 scale 区分，并提供 prefill cache 反量化 dtype 的选择。这说明“支持 FP4 cache”仍是一组格式、attention 后端和阶段策略的组合，不能用一条通用命令覆盖所有 GPU。新方案若采用旋转或向量量化，还需要记录 Q 的对应变换、K/V 编码是否一致以及在线开销。来源：SGLang quantized KV cache

KV 的优先级取决于 workload。短 prompt、短输出、低并发时，权重可能仍占主要内存；长上下文或高并发时，cache 可以成为容量与带宽瓶颈。量化释放的空间可以用于更大 batch，进而提高总吞吐，但这不保证单请求 TPOT 下降。服务引擎还可能预分配固定比例显存作为 cache pool，所以 nvidia-smi 显示的进程显存不下降，并不意味着 cache 量化没有生效；应看可分配 block、可容纳 token 数和实际请求容量。

补充方向：TurboQuant、旋转与内积误差

TurboQuant 把随机旋转、主体量化与残差内积修正结合，目标不仅是逐元素重建，还包括让压缩后向量保留有用的内积关系。它与 KIVI 的分轴整数分组、KVQuant 的 pre-RoPE/稀疏 outlier 处理属于不同设计路线。这里的“3–4 bit”描述编码预算，不表示硬件原生执行同位宽 attention。来源：TurboQuant 方法论文。

Google 的作者介绍展示了特定模型和长上下文任务的压缩结果；这些结果不能解读为任意模型、任意任务都严格无损。部署还要核对额外范数/残差元数据、旋转、解码和实际 attention 路径。vLLM 项目自己的研究也将此类低位存储与硬件 FP8 attention 的计算路径分开比较。作者介绍 · vLLM 项目实验分析。

vLLM v0.31.0 已有 TurboQuant 量化代码目录，但代码存在不等于每个模型、GPU 和 attention 后端都支持。把该目录作为研究入口，实际服务先用本文已列清配置的 FP8 路线建立基线。

KV 失败模式清单

  • 校准范围不足：短文本良好，长文本出现检索失败；按层/head 检查饱和率与 scale。
  • 缓存位置错误：pre-RoPE 与 post-RoPE 的量化假设不一致；核对存储语义与 attention kernel。
  • 首尾 token 特别敏感：仅测平均误差掩盖 attention sink 或关键检索位置的变化；按位置测试。
  • 错误地把分页、淘汰、压缩叠加为相同比例收益：淘汰减少保留 token，量化减少每个 token 字节数；质量风险不同。
  • 量化 kernel 快，服务反而慢：检查写入转换、scale 归约、布局变换、反量化和小 batch 调度开销。
  • 多模态或混合 attention 架构只有部分层采用所设 cache dtype：检查实际层类型与启动日志，不能只看全局参数。

从缓存误差到 attention 输出误差

对于单个 query，写作 \(p=\mathrm{softmax}(qK^T/\sqrt{d})\)、\(o=pV\)。只量化 V 时，固定 p 下误差为 \(pE_V\)；量化 K 时，分数改变导致 p 变化，再通过 V 影响输出。若关键位置的两个分数很接近，小扰动就可能改变相对排序；若分数差距很大，同样扰动可能几乎不影响分布。因此 cache 的全局 MSE 与任务损失不一定线性相关，校准需要关注敏感方向与位置。

RoPE 是特定位置相关的旋转，它保持相应向量范数，却会改变坐标轴上的元素分布。对依赖 per-channel outlier 结构的方案，这种轴变化很重要；对另一些近似旋转不变的表示，影响可能不同。不能因为旋转保持范数就认为量化误差也不变，量化格点通常并不具有连续旋转不变性。这也解释了为什么 pre-RoPE 量化与 post-RoPE 量化属于需要单独实现和验证的设计选择。

Cache 还存在生命周期问题：prefill 写入的历史状态可能在后续数千步被重复读取，而某些 activation 只用于一次矩阵乘。前者的压缩误差持续参与生成，评估必须覆盖完整生成长度。另一方面，自回归分叉又意味着不能简单把每步误差相加得到最终任务损失；需要局部固定输入诊断与完整 rollout 两套证据。

9. outlier 知识地图：先识别是哪一类，再选择处理方式

9.1 “一个最大值很大”并不完整描述问题

outlier 至少要看五个维度：出现在 W、A、G、K/V 的哪一种；集中于固定 channel 还是少量 token；是偶发还是长期存在；出现在 attention 还是 FFN/SwiGLU；是本身的绝对值巨大，还是相对同组普通值巨大。一个 100 并不必然危险：如果同组全是 50–100，量化很容易；一个 1 也可能危险：如果其余值全在 \(10^{-6}\) 附近，它会严重占用共同量尺。真正相关的是组内动态范围和误差落在模型敏感方向上的程度。

9.2 缩小组、平滑、旋转、裁剪和旁路分别改变什么

缩小组只改变哪些数共享 scale，尽量保持原函数。它适合把 outlier 的影响局限在少量元素内。代价是更多 scale 与内核约束。平滑或等价重参数化把一部分范围从一个张量搬到另一个张量，例如对角矩阵 \(D\) 满足 \(XW^\top=(XD^{-1})(WD)^\top\)。这在精确算术中保持 Linear 结果，却可能让 A 更好量化、W 更难量化，因而需要联合选取尺度。把 outlier“迁移”不等于把困难消灭。

旋转使用正交变换重新分配能量，例如 \(XW^\top=(XR)(WR)^\top\)，其中 \(RR^\top=I\)。如果一个向量的能量集中在单一坐标，旋转后可分散到许多坐标，从而降低某些组的峰均比。必须同时变换相配的两个操作数，或把变换吸收进模型参数；随意单独旋转 activation 会改变函数。对于非线性，通常不能把旋转无条件跨过去：\(\operatorname{SwiGLU}(xR)\) 一般不等于 \(\operatorname{SwiGLU}(x)R\)。

裁剪明确把超阈值值截断，例如 \(x'=\operatorname{clip}(x,-c,c)\)。它能把 scale 从极端值手中拿回来，改善大量普通值的分辨率，但会改变尾部信息。阈值应依据目标函数或实验，不应只为降低 MSE 随意截掉承载关键信息的通道。高精度旁路则让少量异常通道、层或元素保留高精度，主体低精度；代价是额外索引、访存、分支或 GEMM。异常集过大时，旁路开销可能吞掉收益。

这些方法可以叠加，但并非可自由拼装的积木。平滑改变 W/A 的分布以后，原来的校准统计会失效；旋转改变了组内结构以后，原来的 group size 选择可能需要重测；裁剪可能改变 backward 的代理规则。建议先给每个变换写清楚它在精确算术中是否等价、在哪一步引入近似，再用端到端质量验证。

9.3 长程 FP8：为什么 SwiGLU 会是单独一章

SwiGLU 的一个标量形式是 \(z=(x^\top w_1)\operatorname{SiLU}(x^\top w_2)\)。当两个投影在同一输入方向上一起变大，且 gate 落在正值区间时，输出可能近似两个大值的乘积，形成比单个线性层更长的尾部。跟踪输入 amax 不足以判断乘积输出的分布；还应跟踪两个分支及其相关性。某些异常值在训练很久以后才逐步出现，因此只跑几百步并不能排除这一问题。

Intel 的长程 FP8 研究明确讨论 SwiGLU outlier amplification，并提出 Smooth-SwiGLU，同时研究 FP8 optimizer moments。它的意义是提供一种“训练动态改变分布，进而击穿低精度假设”的证据；具体改法应作为该论文的联合方案理解，不能把任意版本 SwiGLU 替换都称为等价或稳定。来源：Scaling FP8 training to trillion-token LLMs。

9.4 NVFP4 的 RHT 为什么放在 Wgrad 路径

Wgrad 为 \(G^\top X\)，沿 token 轴做正交变换 \(H\) 时，\((HG)^\top(HX)=G^\top H^\top HX=G^\top X\)。因此可以同时变换 G 和 X，在精确算术中保持结果，同时让二者更适合量化。这与直接在整个模型的前向 residual stream 随处插旋转不同：它针对一对乘法操作数及其共同归约轴，不需要假装变换可以穿过任意非线性。实际量化之后等式只近似成立，评估的是新的量化误差是否更有利。

Transformer Engine 的 NVFP4 recipe 对 Wgrad 使用 16×16 Hadamard 变换，并结合 gradient stochastic rounding；weight 采用二维块缩放以改善转置一致性。这些措施应作为 recipe 的组成部分一起检查，不能把输入 cast 到 E2M1 就称为复现。来源：Transformer Engine NVFP4 文档。

9.5 attention logits 爆炸与低精度上溢如何区分

attention 分数包含 \(QK^\top/\sqrt{d}\)。如果 Q、K 的范数持续增长，logits 可在 FP32 中仍是有限值，却已让 softmax 接近 one-hot，改变优化行为；这属于真实训练动态。另一种情况是同样的 Q/K 在低精度乘法或 reduction 中先上溢，FP32 参考仍正常；这属于数值实现问题。二者可以同时出现。把 softmax 输入减去最大值只能防止 exp 的直接溢出，不能阻止上游 QK 先变成 Inf，也不能逆转 logits 过度尖锐造成的信息损失。

本仓库 Kimi K2 的 MuonClip / QK-Clip 应放到“优化器与 attention 稳定性”分支，而不是简单标成一个 FP8 量化技巧。QK-Norm、调整初始化、控制 Q/K 投影增长可以作用于模型动态；升精度、细粒度 scale 作用于数值表示。它们修复的环节不同，工程上先定位最早异常，再决定措施。仓库译文：Kimi K2 技术报告。

10.1 先区分五种“崩溃”

出现 NaN/Inf 是最显眼的一种，但还有 loss spike 后能恢复、loss 永远有限却持续落后基线、训练正常而导出模型掉点、RL 中 rollout 与训练 log-prob 不一致。它们不能共用一个处理按钮。只有前一类包含明确非有限数；第二类可能是数据或优化器动态；第三类可能是量化噪声持续累积；第四类可能是导出/校准不一致；第五类还可能来自 kernel、dtype 或 MoE 路由差异。回退所有精度能帮助定位，却不自动解释根因。

10.2 建立“最早异常”的证据链

保存异常前 checkpoint 和对应 batch，连同 optimizer、scaler、随机数、scale 历史及数据位置；只保存模型参数可能无法复现。逐层检查输入、量化前、量化后恢复、GEMM 输出和 backward 的统计。建议记录 amax、RMS、关键分位数、非有限比例、饱和比例、零比例以及相对误差。相对误差在参考值接近零时会被放大，应同时看绝对误差和归一化均方误差；仅看 max relative error 容易被一个接近零的元素误导。

再把一次计算的误差拆开：先用高精度原始输入做参考；接着把输入量化并恢复，但仍用高精度 GEMM，得到“输入表示损失”；最后运行真正低精度 kernel，观察新增的“乘加与实现损失”。若第二步已经劣化，优先查分组、scale 与 outlier；若第二步好而第三步差，优先查内部累积、kernel、布局和硬件模式。这个拆分比不断更换全局 dtype 更能解释问题。

参数更新也应单独量化监控。可以跟踪每层 update-to-weight norm，即更新幅度与 weight 幅度之比；再记录 master 更新后，有多少计算副本元素实际发生了编码变化。若 master 在移动而计算副本长期完全不变，可能是更新小于量化格点；若单步更新骤然变大，则查 gradient、二阶矩分母、学习率或异常数据。如果一切都有限却慢慢落后，比较 optimizer 的高精度参考更新，往往比只比较 activation 更有帮助。上述比值是诊断信号，不存在适用于所有层与所有架构的统一安全阈值。

调试时的参考计算还应避免无意改变求和顺序。浮点加法不满足结合律，改变 batch 切分、GEMM tiling、融合顺序或 collective 拓扑都可能产生微小差异；不宜要求所有 dtype 与所有设备逐 bit 一致。合理的比较是在固定配置下判断差异的规模、方向、持续性以及对质量的影响，同时用足够高精度的局部参考确认最早的误差来源。可复现配置与容差说明，比一个没有上下文的“误差为零”更有价值。

当需要局部回退时，可按成本与证据保护 embedding、输出头、norm 统计、softmax、MoE router、attention 或最后若干层。不能把一份 recipe 的“末几层保留高精度”升格成所有模型固定保留四层的定律；敏感层位置随架构与训练配置变化。NVFP4 的官方方法与当前使用指南都把高精度例外当作 recipe 的必要组成，而不是假定全模型所有算子都能降到 4 位。来源：NVFP4 预训练论文。

10.3 可运行的 PyTorch AMP 最小示例

下面使用当前 torch.amp API，按本次检索到的 PyTorch 2.14 文档核对；较旧版本可能仍使用旧命名空间，需要按安装版本检查，本文未验证跨版本兼容。模型参数保持 FP32，autocast 控制算子计算 dtype。它用等大小 micro-batch 演示累积顺序：固定 scale 完成累积，再 unscale、clip、step、update。把 amp_dtype 改成 BF16 时关闭 scaler；这不表示所有 BF16 模型都必然稳定。此代码为教学示例，未在本机 GPU 实跑，也没有验证任何模型的收敛与吞吐。来源：PyTorch AMP API。

import torch
from torch import nn

torch.manual_seed(7)
assert torch.cuda.is_available()
device = "cuda"
amp_dtype = torch.float16  # 可改为 torch.bfloat16
if amp_dtype == torch.bfloat16:
    assert torch.cuda.is_bf16_supported()

# FP32 参数承担高精度参数更新；不把整个模型 .half()。
model = nn.Sequential(nn.Linear(256, 512), nn.GELU(), nn.Linear(512, 32))
model = model.to(device=device, dtype=torch.float32)
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)
scaler = torch.amp.GradScaler("cuda", enabled=(amp_dtype == torch.float16))
micro_batches = 4

for step in range(10):
    optimizer.zero_grad(set_to_none=True)
    for _ in range(micro_batches):
        x = torch.randn(16, 256, device=device)
        target = torch.randn(16, 32, device=device)
        with torch.autocast(device_type="cuda", dtype=amp_dtype):
            prediction = model(x)
            # 明确在 FP32 中计算这个示例的平方误差。
            loss = (prediction.float() - target).square().mean()
            loss = loss / micro_batches
        scaler.scale(loss).backward()

    scaler.unscale_(optimizer)
    # FP16 非有限检查由 scaler.step 处理；不要先手工 step。
    torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
    scaler.step(optimizer)
    scaler.update()

上述顺序有几个可验证的含义。FP16 发生溢出时，scaler.step 会依据其检测结果跳过 optimizer 更新；不能绕过它额外调用 optimizer.step()。每次有效更新只调用一次 unscale_，而且在所有累积完成后调用。若换成真实 token loss，要按有效 token 归一化；若使用 FSDP/ZeRO，要改成框架支持的全局 norm 与 scaler 协同方式。这段单卡代码不是分布式训练模板。来源：PyTorch AMP examples。

10.4 Transformer Engine：选择 recipe，而不是直接把 tensor cast 成 FP8

下面演示同一 Linear 如何由 recipe 控制低精度计算，参数与 AdamW 状态保持 FP32，从而把计算精度实验与参数更新精度实验分开。API 按本文核对到的 Transformer Engine 2.20.2 文档编写；安装环境需要与 GPU、CUDA、PyTorch、TE 构建相容。普通 FP8、MXFP8 与 NVFP4 的设备支持不同，不能在不支持的卡上只改字符串。代码未 GPU 实跑，不承诺示例之外的形状、kernel 路径或性能。来源：Transformer Engine 官方示例。

import torch
import transformer_engine.pytorch as te
from transformer_engine.common.recipe import (
    DelayedScaling, Format, MXFP8BlockScaling, NVFP4BlockScaling,
)

assert torch.cuda.is_available()
assert torch.cuda.is_bf16_supported()
torch.manual_seed(7)

recipe = DelayedScaling(
    fp8_format=Format.HYBRID,
    amax_history_len=16,
    amax_compute_algo="max",
)
# Blackwell 对应支持设备上，可分别测试以下 recipe：
# recipe = MXFP8BlockScaling(fp8_format=Format.E4M3)
# recipe = NVFP4BlockScaling()

layer = te.Linear(1024, 1024, params_dtype=torch.float32, device="cuda")
optimizer = torch.optim.AdamW(layer.parameters(), lr=1e-3)

for step in range(10):
    optimizer.zero_grad(set_to_none=True)
    x = torch.randn(32, 1024, device="cuda", dtype=torch.bfloat16)
    target = torch.randn(32, 1024, device="cuda", dtype=torch.float32)
    with torch.autocast(device_type="cuda", dtype=torch.bfloat16):
        with te.autocast(enabled=True, recipe=recipe):
            y = layer(x)
            loss = (y.float() - target).square().mean()
    # backward 放在 TE autocast 外面，精度仍由前向 recipe 决定。
    loss.backward()
    torch.nn.utils.clip_grad_norm_(layer.parameters(), 1.0, error_if_nonfinite=True)
    optimizer.step()

Format.HYBRID 对应前向 E4M3 与反向 E5M2 的传统 FP8 组合。这里仅更换 Linear 并启用 recipe，未实现一整套 LLM 的敏感层保护、checkpointing、scale 分布式通信、optimizer 压缩或 KV cache。真正实验应从已稳定的 BF16 训练配置出发，一次改变一个维度，核对初始 loss、同 batch 的 Fprop/Dgrad/Wgrad、短程曲线和长程结果，再谈速度。

10.5 怎样判定低精度方案真正成功

第一层是数值可解释：无异常饱和、没有意外丢失大量有效 gradient、master 和 optimizer 更新正常。第二层是收敛：固定 token 预算、数据顺序和学习率计划，对比 BF16 基线，观察多个时间点与训练末期；训练 loss 接近还需看任务质量，尤其是长上下文、代码、数学和长程推理。第三层是系统收益：相同 batch、相同模型、相同硬件下，测量端到端 tokens/s、峰值显存、通信占比以及量化相关 kernel 时间。若容量收益使 batch 可以变大，应把“相同 batch 的速度”和“可用最大 batch 的吞吐”分别报告。

最后还要验证恢复与部署：从 checkpoint 恢复后 scale 历史是否正确、随机舍入是否按预期工作、导出后的 weight 编码是否与部署内核一致、RL 的 rollout 与训练是否采用相容的数值路径。一个只在训练第一百步通过的 FP8 GEMM 单测，无法替代这些验证；相反，一个完整报告也不需要假装每个张量都降到同样精度，保留少数高精度位置往往是总体最合理的预算分配。

11. 各家方案：沿着 W、A、G、KV 与优化器逐项拆开

同一个“FP8 模型”标签，可能指计算使用 FP8、checkpoint 使用 FP8、反向传播保存的激活压缩为 FP8，或者只指部署阶段的某几层。下面以已有译文作为阅读入口，以原始报告与官方实现作为事实依据。表中“未披露”表示所引材料不足以确认该项；它既不等于采用 BF16，也不等于没有使用相关优化。W 指权重，A 指激活，G 指 gradient；优化器与主权重另列，因为它们决定小更新是否能长期积累。

阅读时应先定位阶段，再定位张量和操作。训练中的 Linear 有前向、输入 gradient 和参数 gradient 三种矩阵乘；其中一种用 FP8，不能推出另两种相同。推理又分 prefill 与 decoding，低比特权重主要减少参数搬运，低比特 KV 主要减少上下文状态的容量和访问，两者可能在不同负载下成为主要收益来源。

DeepSeek：从完整 FP8 训练到 FP4 专家与 FP4 KV

DeepSeek-V3：将低精度放到计算、存储、通信三条路径

V3 的代表性不在于“用了 FP8”四个字，而在于它明确展示了一个可训练的混合精度系统：矩阵输入、累加、主权重、gradient 累积、优化器状态和敏感算子各有不同精度。主干计算的吞吐量收益，并不要求把所有状态都降到同样位宽。阅读入口为已有中文译文，证据见V3 原始报告 §3.3 与附录 B。

对象阶段与公开配置为什么这样划分
W：计算副本Linear 的 Fprop、Dgrad、Wgrad 使用 FP8 GEMM；量化权重按 128×128 分块。使大矩阵乘利用 FP8 吞吐量；不把计算副本误认为优化器的主权重。
A：计算与保存一般激活按每个 token 的 128 个通道量化；采用 E4M3。部分反向所需激活保存为 FP8，attention 后 Linear 的敏感输入使用定制 E5M6。小组 scale 减少少数大值对其余通道的影响；保存格式根据反向用途选择。
G：乘法与累积Dgrad、Wgrad 的矩阵乘使用 FP8 输入；用于 batch 累积的权重 gradient 保持 FP32。“FP8 Wgrad”不代表最终 gradient 累积缓冲区也是 FP8。
主权重与 optimizer主权重 FP32，AdamW 一阶、二阶矩 BF16。保留小参数更新的可积累性，同时压缩数量可观的优化器状态。
高精度例外embedding、输出头、MoE gate、归一化与 attention 保留原始较高精度。对误差敏感或计算成本不占主导的操作，降精度的收益不足以抵消风险。
KV cache此处讨论的 FP8 训练配置不能单独确定部署 KV 的完整格式。MLA 的结构压缩与 cache dtype 是两件事。

V3 的 scale 在线依据当前张量小组的最大绝对值计算，避免直接依赖历史 amax 预测当前范围。与一整张矩阵共用一个 scale 相比，细粒度分组缩小了需要共同兼容的数值范围。这里是在表示层面适应 outlier，不要求先将模型中的 outlier 全部删除。

累加精度是另一条独立防线。Tensor Core 能接受 FP8 输入，并不保证长内积具有理想 FP32 累加的数值表现。V3 将部分累加结果周期性转移到 CUDA Core 的 FP32 寄存器，再结合分组 scale 完成累加。由此要区分三个问题：乘数量化误差、硬件内部部分和的误差，以及最终输出 dtype。只检查输出张量写成 FP32，会漏掉中间部分和已经丢失的信息。

反向传播还带来布局问题：适合前向的逐 token 小块，在转置后未必仍适合 Dgrad。V3 没有用一个省事的二维大块覆盖所有激活；其消融显示，对 activation gradient 使用 128×128 块级量化可能在训练很久以后发散。这里的教训是 gradient outlier 可以在 token 之间极不均匀，不能仅凭权重量化表现良好就复用相同粒度。时间较短的小规模对照，也可能漏掉缓慢累积的偏差。

通信同样选择性降精度：MoE dispatch 及对应反向路径可以使用低精度，而 combine 保留 BF16。其原则是沿数据流判断误差如何被后续求和、分支与路由放大。链路带宽下降只是结果；真正需要核查的是发送前在哪个轴上量化、scale 如何传递，以及接收后采用什么精度合并。

DeepSeek-V4：FP4 QAT 与训练稳定性分层处理

V4 将部署的主要参数内存进一步压到 MXFP4，同时保留训练所需的高精度状态。它还把低精度用在索引器，而主 KV 采用另一套混合格式。出处为已有 V4 译文与V4 原始报告；不能把三个位置的 FP4、FP8 合并成一个笼统的“全模型 4bit”。

对象公开方案保留条件与边界
W后训练对 MoE 专家权重进行 MXFP4 QAT；训练侧由 FP32 主权重量化到 FP4，再转换到 FP8，复用 FP8 计算框架。FP4→FP8 的无损承载依赖分组 scale 的范围条件，不能对任意张量无条件断言无损。
ACSA 索引器 QK 路径采用 FP4；索引分数另从 FP32 降为 BF16。索引器分数用于选候选 KV，与主 attention 输出计算不是同一操作。
GQAT 通过 STE 传回 FP32 主权重；部分跨 DP 的 MoE gradient 用随机舍入压为 BF16通信，然后 FP32 求和。传输格式与归约累加格式分离；不能把它写成“所有 gradient BF16”。
KV主 KV 的 RoPE 维度 BF16，其余维度 FP8。按子空间保精度，且与 CSA/HCA 的结构压缩叠加。
optimizerFP32 主权重已明确；Muon 的 Newton–Schulz 运算可采用 BF16 矩阵乘。这不足以补全所有 optimizer state 的逐项 dtype。

V4 的 QAT 前向使用量化后的有效权重，反向通过直通估计器更新主权重。这样既让网络适应低比特扰动，又保留优化器所需的连续参数空间。部署与 RL rollout 则直接使用原生 FP4 权重，取得真实的存储与带宽收益。QAT 中的模拟路径、实际推理内核和主权重应分别记录。

面对训练不稳定，V4 同时处理路由与数值范围：Anticipatory Routing 试图打断路由与 outlier 的反馈；SwiGLU 对线性分支采用 [−10,10] 限幅、门控分支上界设为 10。报告指出这些方法经验有效，但机制尚未完全解释。不能将这一具体架构里的成功扩大为“任何模型裁剪到 10 都不损伤质量”。合理的迁移方法是先观察发生尖峰的层、专家、通道与路由变化，再做受控对照。

BF16 gradient 通信的设计则针对累加误差：先交换局部 gradient，再由接收方用 FP32 求和。若只把标准树式或环式归约的数据类型改成 BF16，低精度中间和可能反复舍入，数值行为并不等价。这里说明通信压缩必须与集合通信算法一起设计。

DeepSeek-V4.1-Flash：KV 4bit 不等于 attention 4bit

V4.1 将重点转向主 KV cache 的持久化和 HBM 占用。其关键是区分“为矩阵乘选择格式”和“为缓存选择格式”：前者受 Tensor Core 原生支持约束，后者只需能高效反量化给计算内核。阅读已有译文与V4.1 原始报告 §2.4.4。

省略全局 scale 有明确的范围论证：归一化后的潜在 KV 及 RoPE 保范数性质给出幅值约束，所选局部格式有足够动态范围。它是针对这类张量的判断，不能直接用于未经归一化的残差或 SwiGLU 中间激活。报告还明确给出更敏感的 SWA KV 例外，说明“同为 KV”仍可能需要按路径设计精度。

评估 KV 方案需要拆出四项：结构改变少存了多少元素，低比特少用了多少字节，scale 与布局增加多少元数据，反量化及跨层复用影响多少延迟。长上下文下的总显存下降，不等于相同比例的 attention 算力下降；实际吞吐量还取决于读取模式、batch、命中率和内核实现。

Qwen3.8-Next：先控制写入范围，再压缩残差状态

3.8-Next 的公开设计使用 GR、gated attention 与 GDN 门控约束写入 residual stream 的内容，使 residual state 的分布更适合 FP8 存储，并融合读写及归一化以减少数据搬运。其证据是Qwen3.8-Next 架构报告。这里“门控→范围更可控→低精度存储”的因果设计，比简单改变一个 dtype 更值得复用。

残差分支变宽后，额外状态会增加 decoding 的内存流量。FP8 存储降低每次遍历状态的字节数；融合内核则减少遍历次数。两者解决不同部分的成本，因此应同时记录：单个元素位宽、分支数量、每块读写次数和 scale 开销。否则，“字节减半”可能被误读成整个模型 decoding 延迟减半。

在稳定性分析中，报告比较不同学习率和门控设置下的 activation 极值、gradient 范数与 loss spike。值得学习的是观察方式：中位数 gradient 较大不必然意味着更不稳定，极少数尖峰及其时间相关性可能更关键。仅比较平均 loss 或平均梯度范数，可能看不到导致低精度崩溃的尾部分布。

与 gated attention、residual sink 研究连接

gated attention 译文与attention / residual sink 统一视角译文为理解 Qwen 的架构路线提供机制背景，原始材料为gated attention 论文及outlier 驱动重缩放研究。这些工作提醒我们：某些 outlier 与归一化共同提供调节信号幅度的功能。直接消除 outlier，可能同时消除了模型依赖的重缩放机制。

因此要区分两个目标：让现有张量更容易表示，以及改变网络使其不再需要极端激活。前者可用细粒度 scale、平滑、旋转与混合精度；后者需要架构与训练对照。门控为网络提供显式调节通道，可能降低其制造巨大坐标值的需求。这个解释在所研究设置中有实证支持，但不应写成所有模型的唯一 outlier 成因。

K2 是最适合纠正“看到 FP8 就认为 FP8 训练”的反例。它将不敏感激活压为 FP8 保存，并没有因此在主干计算中使用 FP8。阅读K2 译文、K2.5 译文与K2 原始报告、K2.5 原始报告。

对象K2 / K2.5 已披露事实作用

AK2 将 MoE up projection 与 SwiGLU 输入按 1×128 小块保存为 FP8 E4M3，scale 为 FP32；K2.5 同样压缩不敏感激活，并结合选择性重计算和 CPU 卸载。减少为反向传播保留的显存，而不要求所有算子低精度执行。

保存激活本质上是在时间轴上压缩信息：前向产生张量，经过若干层或流水线阶段后，反向再读回。重计算用额外 FLOPs 换存储，卸载用主机容量与传输换 HBM，量化用数值误差换字节数。它们可以组合，也应分别评估；一次显存下降不能全部归因于 FP8。

判断是否“不敏感”不能只看前向输出误差。相同输入可能服务于多个反向算子，其中某条路径对微小误差更敏感。正确的对照是从保存张量出发追踪所有消费者，核查反向 gradient、长期收敛与最终质量。K2 的保守选择说明，存储压缩可作为在计算全面降精度之前的独立工程步骤。

PrefixQuant 与 P-GPTQ：前缀 outlier 会污染校准

初始 token 的激活分布可能明显偏离稳定位置。即使只量化权重，GPTQ 使用的输入二阶统计也会被极大激活主导，造成校准目标偏向少量特殊位置。P-GPTQ 在计算 Hessian 近似时排除这些初始位置，PrefixQuant 则通过预置前缀状态隔离推理激活 outlier。两者处理的环节不同：一个改变校准统计，一个改变推理时进入普通路径的激活分布。

这里应避免“删掉 outlier 即可”的误解。被排除的是校准统计中的特定位置，并不意味着在正常生成时删去用户 token；预置前缀也不是随意修改语义提示。复现需要核对固定前缀、位置编码、被缓存状态的精度以及目标模型的具体实现。换模型后初始位置数量与稳定区间未必保持不变。

三值权重为何不同时量化激活

端侧的 W 与 A 不一定具有相同瓶颈。低 batch decoding 中，加载大权重往往占据重要成本；激活量化若需要额外扫描、scale 和转格式，未必得到硬件支持的更快算子。MiniCPM4 选择对三值模型的权重做 QAT，而不为追求更小的数字标签额外量化激活。这是按实际执行成本设计方案的例子。

从 FP8 阶段转入三值 QAT，学习率重新 warmup 在其试验中很关键。阶段切换引入新的有效函数与量化误差，不能假定继承原学习率就能平稳适配。但这一观察也不构成固定配方：需核查模型规模、QAT token 预算、学习率曲线及性能目标，不能把小模型探索中的数值直接照搬到大模型。

量化之后，投机采样需要重新找工作点

权重压缩让目标模型 decoding 更便宜后，草稿提出更多 token 的相对成本与验证收益会变化。原先适合高精度目标模型的草稿长度、树宽或候选数量，未必仍然最佳。此外，草稿模型量化的误差可能降低接受率；平均接受长度相近，也不自动意味着端到端吞吐量相近，因为草稿、验证和调度的耗时都在变化。

因此比较端侧组合方案时，需要至少报告：目标 W/A 格式、草稿 W/A 格式、平均接受长度、每步草稿耗时、验证耗时和端到端速度。将“4bit + speculative decoding”的各项单独加速倍数直接相乘，通常缺乏依据。结构稀疏与缓存管理也必须在同一负载下计量，避免重复计算收益。

这里最重要的评估启示是检查分布尾部。少量选择题基准的平均准确率相近，不意味着所有输入都安全通过量化路径。应观察大规模生成中坏回答率、奖励分布、logit 或概率漂移，并专门覆盖日期、数字、罕见 token 和异常长输入等压力条件。对于偶发故障，均值容易掩盖真正影响可用性的尾部事件。

Google Gemma：QAT 为目标推理格式服务

Gemma 3 译文和Gemma 3 原始报告讨论少量步骤的 QAT，并以原始模型概率作为目标，面向逐通道 INT4、分块 INT4 等表示。该流程说明量化适配可以带有蒸馏性质：教师提供较平滑的输出目标，帮助低比特学生恢复行为。

Gemma 4 译文及Gemma 4 原始报告进一步涉及移动端混合 INT2/INT4 权重配 INT8 激活、Q4_0、图像编码器 W8A8、音频编码器按层簇混合位宽，并通过块内标量缩放帮助 FP16 推理稳定。这说明“端侧模型”也不必只有一种统一位宽。

多模态编码器与语言模型应分开评估。图像输入的动态范围、音频长度和预处理误差，可能与文本残差不同；同一个 W8A8 标签下，静态／动态 activation scale、逐通道／逐块粒度和校准数据仍决定质量。磁盘体积减少、峰值内存减少与延迟减少，也必须分别测量。

NVIDIA Nemotron-H：E4M3 W/A、E5M2 G 与 current scaling

Nemotron-H 译文与其原始报告提供了与 V3 不同的 FP8 配方：用 E4M3 表示权重和激活，用 E5M2 表示 gradient；每个张量根据当前最大绝对值计算一个 scale。更多指数位给 gradient 更大的范围，代价是较少尾数位；这与 V3 通过细粒度 scale 为所有相关张量争取 E4M3 精度的设计不同。

对象公开配置与例外
W / A线性层前向与反向参与 FP8，W/A 为 E4M3；逐张量 current scaling；最前和最后四个线性/GEMM 位置保留 BF16。报告概述与细节对“GEMM／层”的表述粒度有差异，不能扩写为前后四个完整 transformer block。
Ggradient 张量 E5M2；不能据此将 optimizer gradient 累积缓冲区也写成 E5M2。
KV / optimizer此处 FP8 配方没有补齐完整缓存与状态格式；Mamba 状态另行核查。

其缩放保留最大值，小到无法表示的元素则下溢为零。报告观察到 FP8 loss 与 BF16 有小幅差距，但下游质量并不严格按 loss 排序；训练后期的小 gradient 被置零，是作者对差距变化的一个解释，而非已经证明的唯一机制。值得纳入实验设计的是长 token 训练和足够模型规模：短期、小模型上表现正常，不保证尾部误差与后期微小更新仍然正常。

Nemotron 3 Super：NVFP4 已进入预训练，但并非所有状态都 4bit

Nemotron 3 Super 译文及其官方报告明确介绍大规模 NVFP4 预训练。必须把预训练配方与发布 FP8、NVFP4 checkpoint 的后量化配方分开：同一模型在训练和服务时的分组轴、敏感层例外与 scale 选择可以不同。

对象预训练部署与例外

报告没有回避下溢：低范数通道与较高幅值通道共用二维权重块时，Dgrad 中的细小信息可能消失，并传到前一层 Wgrad；前向下溢也可能使后续 Wgrad 置零。将部分训练模型切回较高精度，可帮助分辨哪些零来自表示能力，而不是目标函数恰好产生精确零。其试验还显示提高到 MXFP8 能改善 loss 轨迹，却未必改善下游准确率，因而“loss 更接近 BF16”与“最终模型更好”应分别验证。

Mamba 状态的案例尤其重要：即使 W/A 保持 BF16，仅把循环缓存转为 FP16，也可能改变回答冗长程度。报告用沿状态维度的分块 INT16 加 FP32 scale，或 FP16 随机舍入，缓解递归量化误差。这里不是标准 KV：普通 KV 的某个历史值被读取，循环状态却反复更新，过去的误差参与未来状态。随机舍入在期望上减轻系统性偏差，不保证每条轨迹误差为零；应观察长序列行为与尾部质量。

Step 5 Preview：FP32 hidden state 与 RMSNorm 参数解决两类不同问题

Step 5 Preview 译文对应官方技术文章。其窄而深架构中，混合 FP8 训练仍配 FP32 hidden state 及相应 gradient。它揭示“GEMM 更低精度、跨层状态更高精度”可以同时成立；不能用一个统一 activation dtype 描述整条网络。

对象公开方案解决的问题
W / A混合 FP8；跨层 hidden state FP32。深层隐藏状态中巨大激活可能爆炸，保留跨层数值空间。
Ghidden state 对应 gradient FP32。不代表所有 Linear 的乘数或所有参数 gradient 均 FP32。
RMSNorm gamma零中心形式中 gamma 用 FP32。避免 gamma 接近 −1 时 BF16 离散步长使有效系数 1+gamma 在零与邻近值间跳变。
KV / 发布存储FP8 KV QAT；部署组合包含 MXFP4 权重存储。整体容量收益同时来自 EP、CPU 卸载及缓存优化，不能全部归给 KV FP8。
optimizer文章未逐项公开完整状态 dtype。FP32 gamma 不等于所有 optimizer state FP32。

零中心 RMSNorm 的问题比“BF16 不够精确”更具体：有效缩放是 1+gamma。某些巨大激活通道对应的有效缩放很小，所以 gamma 靠近 −1；BF16 无法平滑表达其细微变化，通道可能完全关闭后又因扰动打开。将 gamma 本身改用 FP32，改善的是参数抵消附近的分辨率；hidden state FP32 则改善跨层激活与 gradient，两个措施不可互换。

RL 中，Step 5 在 staleness=0 条件下实现 trainer 与 rollout 的逐比特对齐，包含 SWA、MTP、Top-k 与归约；其优化还使结果不随 TP 大小改变。这比“相同 dtype”强得多，但条件必须保留：异步权重陈旧、随机采样状态或不同输入并不会因此自动消失。文章报告的低于 10% 开销属于其系统，不是所有部署都能得到的通用成本。

Ling / Ring 2.6：专家 FP8，attention/shared expert BF16，head FP32

Ling / Ring 2.6 译文及原始报告明确采用模块感知的混合精度，而非统一替换全部 Linear。它还强调续训应加载 FP32 optimizer 主权重，因为从 FP8 发布权重反量化出的 BF16 副本已经无法恢复丢掉的信息。

对象公开配置

其思路是把容量占比大的路由专家量化，同时在控制输出分布的 head 和数值敏感 attention 保精度。为了减小开销，再融合 RMSNorm、SwiGLU 与量化，并用 Split-K 改善小 batch GEMM 的并行度。硬件利用率不足时，低位宽并不自动更快；量化后的 kernel 仍要有足够并行任务和合理访存。

Intern-S2-Preview：混合模型中的 recurrent state 也需明确保精度

Intern-S2-Preview 译文与原始报告将专家 Linear 配为 FP8、其他层 BF16；apply_rope、RMSNorm、MoE router、Gated DeltaNet 循环状态及 LM head 采用 FP32，并使用 R3 回放 rollout 专家选择。

W / AGKV / 循环状态optimizer
专家 FP8，其余一般 BF16，敏感操作 FP32。材料未逐项给出所有 gradient 与累积格式。明确 Gated DeltaNet 循环状态 FP32；不能以此确定所有 attention KV 格式。未补齐状态逐项 dtype。

这个案例使“第四类状态”更完整：传统讨论 W/A/G/KV 时，混合模型还需要单列 recurrent state。它既不是训练时仅保存一次的 A，也不是可逐 token 独立读取的 KV。即使用户关注的总框架仍保留四大类，实际规格表也不能遗漏循环状态与其更新算术。

GLM-5：INT4 QAT 与 Ascend W4A8 是不同阶段的配方

GLM-5 译文及原始报告在 SFT 阶段引入 INT4 QAT，并使用训练与离线权重量化都适用的内核，使相应量化行为逐位一致。报告另外介绍 FP8 rollout 和面向 Ascend Atlas 的 W4A8 部署，不能把这些拼成一个未披露的“统一 INT4 训练、INT8 activation”流程。

对象端侧服务器

MAI-Thinking-1 译文与官方报告区分预训练和 RL：预训练默认权重／激活 BF16，前向 GEMM E4M3、Dgrad E5M2、Wgrad BF16、gradient 累积 FP32；FP8 scale 使用 1024 步 amax 历史。RL 则在 learner 与 rollout 两侧均采用 BF16，以缩小数值差异。

MAI 的路径提供一个必要反例：有些系统选择让 RL 保 BF16，而非追求最低位宽。理由是跨引擎微小 logprob 差异会在长 rollout 及重要性校正中影响稳定性。即使使用 BF16，仍配路由与 top-p mask 回放；精度提高与执行语义对齐是两个独立手段。

延迟 scale 的历史也是训练状态。如果恢复 checkpoint 时只加载权重和 optimizer，却丢失 amax 历史，接下来一段时间的量化行为可能改变。current scaling 与 delayed scaling 的差别不只是一个计算开销选项，还决定重启、异常 batch 与分布突变时系统如何响应。完整可复现记录应包含 scale 配方及其恢复规则。

12. RL 的低精度：必须对齐参数、路径和采样分布

RL 将低精度问题从“固定模型的近似计算”扩展为“数据由当前模型自己产生，再用这些数据更新自己”。生成轨迹的引擎与计算 loss 的训练引擎通常不同，还可能使用不同并行、kernel、cache 和采样实现。误差不仅改变输出，还会改变后续训练数据及估计的概率比。因此，RL 方案必须同时记录 rollout、trainer、reference 与 teacher 的有效数值路径。

四层一致性：从权重到概率

层次要核查的量典型偏差对应措施
参数一致性更新后的主权重、QDQ 后权重、发布给 rollout 的版本。trainer 评估高精度 W，rollout 使用低比特 W，或者量化规则不同。QAT、与部署内核一致的 QDQ、明确权重版本。
运算一致性A 格式、scale、accumulator、舍入、融合与归约顺序。相同名义 dtype 产生不同有效函数。核查内核约束与逐算子误差，避免仅比较标签。
路径一致性MoE 专家索引、离散 top-k、缓存复用。微小 score 差异翻转专家选择，后续计算不再是小扰动。Rollout Routing Replay 等路径记录与回放。
概率一致性温度、top-k / top-p 候选集、归一化分母、token mask。轨迹来自受限候选分布，训练却按完整词表概率解释。记录候选集合并使用相同定义重算概率。

前三层对齐后仍可能出现第四层差异。top-k 或 top-p 采样把部分词表排除，再重新归一化；完整词表 softmax 的 log-probability 与采样器实际分布不是同一个数。是否采用该概率作为某个 RL 目标，必须与算法定义保持一致；不能一方面收集受限分布轨迹，一方面没有说明就用另一种分母解释其概率。

反过来，概率定义一致也不代表有效模型一致。若 MoE 选择翻转，trainer 给同一 token 计算的隐藏状态来自另一组专家；如果 rollout 的低比特参数没有被 trainer 模拟，loss 面向的函数与行为模型仍有偏差。定位问题时，应由参数版本开始，逐层排除，避免将所有异常统称为“FP8 不稳定”。

公开案例如何对应这四层

Kimi K3 明确将 SFT 与 RL 纳入同一 MXFP4/MXFP8 QAT，并让 rollout 与训练共享量化方案，见K3 原始报告。这建立的是部署感知的训练目标；它并不自动宣称所有 kernel 逐位相同，也不能据此补全未公开的 gradient 与 optimizer dtype。

DeepSeek-V4 的训练侧可通过 FP4→FP8 承载模拟量化后的专家，rollout 使用原生 FP4；两者旨在表示同一量化后的有效权重，见V4 原始报告。核查重点是反量化条件、scale 布局和反向使用的权重，而不是要求训练和推理必须调用同一个 kernel。

MiMo-V2.6 将这件事展开到参数 QDQ、路由回放和候选集归一化，见V2.6 原始报告 §4.6。它说明有效权重相同只是必要的一层；离散选择与采样器语义仍需显式控制。MiMo-V2-Flash 的训练／推理均使用 FP8，也应结合这套分层方法解读，而不是把相同 dtype 当作一致性的充分证明。

精度不匹配如何进入 policy ratio 与 KL

许多 RL 目标依赖当前策略与行为策略的概率比。将 log-probability 的差记为 \(\Delta\)，概率比涉及 \(\exp(\Delta)\)；因此看似较小的系统性 log-probability 偏差，可能经指数与长轨迹累积放大。这个关系解释了为何 rollout 与 trainer 的数值差异值得单独监测，但不能据此断言任意 FP8 误差一定导致训练崩溃：具体影响还取决于偏差分布、clip、mask、importance weighting 和任务奖励。

KL 也需要明确比较的是哪两个有效模型。如果 reference 是高精度版本，而 policy rollout 是量化版本，观察到的 KL 可能同时包含策略学习和表示改变。教师蒸馏同理：应明确 teacher 的量化状态与推理路径。对照实验应尽量让变量单独变化，避免把量化引入的基线漂移误判成策略更新过大。

检查时不仅看全 batch 平均值，还应查看 token 级 log-probability 差的分位数、极值、与专家翻转的相关性，以及长回答后半段是否漂移更大。少数异常 token 若恰好落在 reward 或终止行为关键位置，可能对任务造成远大于平均数所显示的影响。

阶段转换：QAT、优化器状态与冻结策略

从 SFT 进入 RL，可以同时发生精度变化、学习目标变化与数据分布变化。一个稳妥的实验设计是先在固定 checkpoint 上测量量化造成的漂移，再启用更新，随后扩展到真实 rollout。这样能区分纯推理近似误差、反向数值误差和策略优化本身的问题。是否重置 optimizer、重新 warmup 或冻结 router，应作为明确实验变量记录。

MiMo-V2.6 继承 SFT 的 FP32 主权重与 Muown 行状态，并冻结 router；MiniCPM4 的三值 QAT 研究则强调阶段转换重新 warmup 的作用。它们的共同点是认真处理转换，不是提供同一个通用超参数配方。低精度训练状态不能仅由发布 checkpoint 的体积推断，也不能假定恢复一份低比特权重就能恢复原来的优化轨迹。

投机采样：目标、草稿与验证需要分别标注精度

RL rollout 为减少成本常用 speculative decoding。精度表至少应有三行：目标模型、草稿模型、验证路径。草稿低精度可能改变建议分布与接受率；目标模型低精度改变的是实际被优化的行为策略。接受长度只是中间指标，最终还需测量完整轨迹的生成耗时与训练吞吐量。

MiMo-V2.6 的 FP8 草稿属于独立优化，不能用它给目标专家或 KV 填写 dtype。MiniCPM4 关于量化后草稿长度的观察也提醒，目标模型更快之后，原来的 speculative 工作点可能失去优势。RL 中还要确保收集的是最终验证后的 token 及其正确概率，不能把草稿提议的概率直接当成目标策略概率。

13. 硬件边界：Hopper 与不同 Blackwell 必须逐层核验

“支持一个 dtype”至少有五层含义：框架能建立张量、文件能保存、loader 能读取、某个算子能执行、目标 shape 下有快速原生 kernel。前四层即使成立，也不能证明获得了该格式宣传的吞吐。可靠记录应包含 GPU 型号与 compute capability、驱动、CUDA、PyTorch、运行时版本、实际选中的 GEMM 与 attention 后端。格式、指令和软件支持的集合随版本改变，不能靠 GPU 家族名称替代核查。

H100、H200 与 H20

H100 与 H200 同属 Hopper，核心区别不能概括为“H200 支持更低 bit”。NVIDIA 的 HGX 参考架构给出的 SXM 配置分别为 H100 80GB HBM3、H200 141GB HBM3e，并列出不同显存带宽；这主要改变可容纳模型、cache 与请求的空间，以及内存瓶颈。PCIe、SXM、NVL 等产品形态还需继续区分。H20 不能拿 H100 的计算规格代替；本报告未取得足够明确的当前 H20 官方规格来给出一组数值，故不填推测性表格。部署时应对实际 H20 机器做 kernel 与 workload 核验。来源：NVIDIA HGX components

Hopper 有原生 FP8 运算能力，但没有因此变成原生 NVFP4/MXFP8 Tensor Core 平台。它可以通过软件把细粒度 scale 应用于普通 FP8 GEMM，也可以用混合精度 kernel 读取低 bit 权重；这些与 Blackwell 的原生 microscaling 路径不同。“FP8 block scaling 可以在 Hopper 上执行”与“MXFP8 在 Hopper 上原生加速”不能互换。来源：CUDA Hopper tuning guide；TE 2.20.2 MXFP8

普通 FP8 block、MXFP8、MXFP4、NVFP4 的分界

普通细粒度 FP8 可给一个 tile 或一段 activation 保存 FP32 scale，缩放的应用方式由软件和指令路径决定。MXFP8 则把 32 个元素与一个 E8M0 的 power-of-two scale 配对。NVFP4 使用 E2M1 数据、每 16 个元素的 E4M3 scale，并叠加 tensor 级 FP32 scale。MXFP4 与 NVFP4 虽然都使用 4 bit 浮点数，也不能当作一个格式读取：scale 类型、组大小和布局都不同。来源：NVIDIA NVFP4 inference

以元数据估算，单层 1D NVFP4 表示中的主体是 4 bit，另有每 16 元素一个 8 bit scale，即约 4.5 bit/element，再加 tensor scale 与对齐；不是恰好 4 bit。真实权重 recipe 可能使用 2D scaling，平均成本应重新按实际 block 布局计算。把 4 bit payload 与整份 checkpoint 的平均位宽分别报告，才不会把压缩率夸大。

累加：格式变小后仍要保护求和

乘数 dtype、累加寄存器 dtype 和实际累加精度是三个问题。PTX 对具体 MMA/WGMMA 变体规定了操作数与结果类型；某个 API 返回 BF16 结果，不代表中间求和也是 BF16，而返回 FP32 也不应被解释为所有内部步骤都等同于逐项 IEEE FP32 运算。训练报告中的定期高精度提升等技巧，正是针对长归约链中的误差问题。分析推理 kernel 时应检查指令、分段累加与 epilogue，不用一个“FP32 accumulation”词组概括所有实现。来源：PTX ISA 8.0

量化性能的最终判据是完整路径：原生低精度矩阵乘省下的时间，是否大于 scale 归约、cast、transpose、swizzle、拆包、反量化与同步增加的时间。大 prefill 与小 decoding GEMM 的结论可能不同；Dense Linear 与 MoE grouped GEMM 的结论也可能不同。矩阵 shape、路由 token 数和 batch 需要与精度方案一起决定。

流程三：校准 Q 与 KV，再部署联合 FP8 attention 路径

本例继续使用已有的 LLM Compressor 0.14.0 量化环境与 vLLM 0.31.0 推理环境。按 vLLM 固定版本官方示例同时校准 Q 与 KV，不是只改变 cache 存储的纯 KV 消融。示例使用 Llama-3.1-8B-Instruct，下载前需要在 Hugging Face 获得模型访问权限，并在本机完成账号认证；不要把 token 写入脚本。512 条、每条最多 2048 token 只是官方起点，正式实验应覆盖目标业务分布。来源：vLLM v0.31.0 Q/KV 校准示例

# 保存为 calibrate_attention.py，以 .venv-compressor/bin/python 执行
from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer
from llmcompressor import oneshot
from llmcompressor.modifiers.quantization import QuantizationModifier
from compressed_tensors.quantization import QuantizationArgs, QuantizationScheme

model_id = "meta-llama/Llama-3.1-8B-Instruct"
output_dir = "./Llama-3.1-8B-Instruct-QKV-FP8"
samples, max_seq_len = 512, 2048
model = AutoModelForCausalLM.from_pretrained(model_id, torch_dtype="auto")
tokenizer = AutoTokenizer.from_pretrained(model_id)
ds = load_dataset("HuggingFaceH4/ultrachat_200k", split=f"train_sft[:{samples}]")
ds = ds.shuffle(seed=42)

def tokenize(example):
    text = tokenizer.apply_chat_template(example["messages"], tokenize=False)
    return tokenizer(text, padding=False, max_length=max_seq_len,
                     truncation=True, add_special_tokens=False)

ds = ds.map(tokenize, remove_columns=ds.column_names)
fp8_args = QuantizationArgs(num_bits=8, type="float", strategy="tensor")
recipe = QuantizationModifier(
    config_groups={
        "attention": QuantizationScheme(
            targets=["LlamaAttention"], input_activations=fp8_args,
        )
    },
    kv_cache_scheme=fp8_args,
)
oneshot(model=model, dataset=ds, recipe=recipe,
        max_seq_length=max_seq_len, num_calibration_samples=samples)
model.save_pretrained(output_dir, save_compressed=True)
tokenizer.save_pretrained(output_dir)

这里没有配置 Linear 权重量化；主要学习并保存 attention 的 Q/K/V scale。targets=["LlamaAttention"] 是对应模型类名，不应原样用于其他架构。需要 per-head 时，可按官方支持把 strategy 改为 attn_head，同时检查 Flash Attention 后端；本例选择 per-tensor 以减少额外条件。v0.31.0 已移除 --calculate-kv-scales，校准由上述离线步骤完成。

其他路线怎样接入

需要 NVIDIA NVFP4 时，使用 ModelOpt 的对应模型 recipe 并检查部署导出格式；它提供 MLP-only、experts-only 等选项，敏感 attention 保持较高精度是有意设计。SGLang 应读取其自身的量化与 KV 支持表，不能直接复制 vLLM 参数名称。llama.cpp 则使用 GGUF 与 llama-quantize 等工具，imatrix 与逐 tensor 类型也是其自己的体系。三者都应保留原始高精度 checkpoint，避免反复从已量化权重再量化。来源：llama.cpp quantize 源码

量化前后的发布产物应该保存什么

一次可复核的量化至少保存：原模型 revision、量化工具与依赖版本、完整 recipe、校准数据标识与采样方式、随机种子、被跳过层、scale 和权重格式、质量评估结果以及实际部署后端。只上传压缩权重而没有 tokenizer 或 chat template，可能使调用方采用不同输入协议；只保存一个模型名，又可能在上游更新后无法重现。

导出端的 API 成功不代表推理端已经正确消费了每个 scale。应抽样核对张量 shape、scale 数量、忽略层和加载日志，然后进行固定 prompt 的 logits 或生成检查。若 loader 自动重排权重，记录重排是否只改变布局，是否额外创建了常驻高精度副本。多卡时分别检查每个 rank 的 shard 和 scale；单卡成功不能替代 tensor-parallel 路径验证。

部署前还要区分 cold start 与稳态。在线量化或首次编译会增加启动时间，并可能需要暂时加载原始权重；稳态峰值显存足够，不代表加载阶段也足够。服务重启频繁时，导出一次可直接加载的压缩模型可能更有意义；长时间运行时，则更应关注每请求成本。这些成本属于完整系统收益的一部分，应与 token/s 同时报告。

15. 如何证明方案有效：质量、稳定性与速度一起测

建立不会混淆变量的对照

先固定模型 revision、tokenizer、chat template、上下文设置、sampling、输出预算、硬件数量与并行配置。逐项比较 BF16 基线、只压权重、权重加 activation、再压 KV。若一次改变了模型、精度、推理引擎和 GPU，就只能报告系统组合的效果，不能得出某个量化算法快多少。实际业务可以最终选择整套更好的组合，但归因实验与部署选型应分开。

实验固定内容主要回答的问题
W-only 消融模型、A、KV、上下文权重压缩本身损失多少质量、节省多少内存
A 消融W 格式与 KV低精度 GEMM 是否值得量化与 cast 成本
K/V 独立消融权重与输入任务误差主要来自 K、V 还是组合
服务容量测试延迟目标与请求分布低精度能否在 SLA 下接更多请求
长上下文压力测试长度、检索位置、输出预算scale 与 cache 在目标长度是否稳定

质量不能只看一个平均分

至少分别记录困惑度或 teacher-forced logit 变化、知识问答、数学/代码、长上下文检索、多轮工具调用，以及实际业务任务。对于长 CoT，应同时记录正确率、输出长度分布、重复与截断；量化可能改变模型采用的推理路径。低平均损失不保证少见关键行为不退化，少量示例“看起来正常”也不构成准确率评估。对样本数较少的任务报告不确定性，避免把波动当作稳定提升。

检索任务应改变证据位置、干扰信息密度与多跳要求；只有单一 NIAH 任务通过，不能证明长文总结、跨段关联和完整生成没有退化。对代码与 JSON 输出，编译、单元测试和 schema 校验比人工看文字更明确。对工具调用，还要区分选对工具、参数合法与完成任务；量化引入的细微 logit 扰动可能首先表现为格式或边界错误。

数值诊断：找到第一个失真的位置

收集 amax、饱和比例、被量化为零的比例、scale 分布、层输出相对误差和信噪比。先用同一个高精度前缀输入比较每层，再逐步允许前面层使用量化输出，区分局部误差与累计误差。遇到异常先确认权重/scale 是否按正确轴加载、tensor parallel 切分是否一致、RoPE 是否在预期位置执行，以及 dtype 是否被不适当转换。没有 NaN 不等于没有数值问题。

如果只是推理质量退化，不应称为“训练崩溃”；如果正在 QAT 或量化恢复训练，则需要额外记录 loss、gradient norm、更新幅度、optimizer 状态与 checkpoint 恢复过程。把推理 repetition、训练 loss spike、浮点 overflow 与通信错误分开，才能选择正确修复：换校准、恢复高精度、调整 clipping、修改 scale 或修复 kernel 的作用对象各不相同。

速度与显存的最小记录表

  • 硬件：精确 SKU、GPU 数量、compute capability、互连、功耗策略。
  • 软件：驱动、CUDA、PyTorch、vLLM/SGLang 等版本或 commit、量化导出版本。
  • 实际配置：W/A/K/V 格式、scale 粒度、敏感层例外、Linear/MoE/attention kernel。
  • 请求：输入/输出长度分布、并发、到达率、warmup、prefix cache 命中率与失败数。
  • 延迟：TTFT、TPOT/ITL、端到端延迟，至少区分典型值与尾延迟。
  • 吞吐：输入和输出 token/s 分开，说明是否混合计算；SLA 下的有效请求吞吐。
  • 内存：权重常驻、cache 容量、工作区、峰值和预分配；不能只看磁盘模型大小。
  • 质量：相同基线下的任务分数、输出长度与失败类型，保存可复核的样本。

Prefill-heavy 与 decode-heavy 至少各选一组：长输入短输出主要检验 prompt 处理与 attention；短输入长输出更突出反复读取权重与 cache；长输入长输出测试容量和持续状态误差；高并发则检查批处理与排队。不能把单请求 tokens/s 与大 batch 总吞吐直接相除，宣称普遍加速。vLLM 官方对 FP8 KV 的讨论也按 prefill/decode workload 分开考察。来源：vLLM FP8 KV 与 attention 实测方法

最后做一次可逆的决策：若 W4A16 质量和速度都满足要求，就不必因位宽更小而增加恢复训练；若 FP8 能稳健满足吞吐，就先把 KV 与调度的瓶颈测清楚；若只有 NVFP4 才能满足容量，再把混合精度例外、校准或 QAT 的成本纳入选择。低精度的目标是用可接受的误差换取目标系统的收益，位宽本身只是控制变量。

五组必须分清的概念

  • PTQ / QAT / QLoRA：训练后压缩、在训练中模拟或执行部署量化、冻结量化底座后训练低秩 adapter。
  • FP8 / block FP8 / MXFP8：元素位宽相同并不意味着 scale 格式、分组或硬件指令相同。
  • activation gradient / weight gradient：Dgrad 与 Wgrad 的输出，分布和后续累积要求不同。
  • KV compression / KV quantization：改变缓存结构或数量，与减少每元素位宽可组合，但收益不能简单相加。
  • 能加载 / 能原生计算 / 能加速 / 质量合格：四个独立验证结果，任何一个都不能代替其余三个。
