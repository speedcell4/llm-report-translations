摘要

长度泛化，即从较小的训练上下文长度泛化到更长上下文的能力，是开发基于 Transformer 的语言模型时面临的一项关键挑战。位置编码（PE）已被确定为影响长度泛化的主要因素，但不同 PE 方案对下游任务外推的确切影响仍不清楚。本文开展了一项系统性实证研究，比较仅解码器 Transformer 在五种不同位置编码方法下的长度泛化表现；这些方法包括绝对位置 embedding（APE）、T5 的相对 PE、ALiBi 和 Rotary，以及不使用位置编码的 Transformer（NoPE）。我们的评估涵盖了一系列推理与数学任务。研究结果表明，ALiBi、Rotary 和 APE 等最常用的位置编码方法并不适合下游任务中的长度泛化。更重要的是，NoPE 在不需要额外计算的情况下，表现优于其他显式位置编码方法。我们从理论上证明，NoPE 能够表示绝对和相对两种 PE，但在使用 SGD 训练时，其 attention 模式主要类似于 T5 的相对 PE。最后，我们发现 scratchpad 并不总有助于解决长度泛化问题，而且其格式会对模型表现产生很大影响。总体而言，我们的工作表明，对于仅解码器 Transformer 向更长序列良好泛化而言，显式位置编码并非必不可少。

1　引言

从较小的训练上下文长度泛化到更长上下文的能力，通常称为长度泛化，是基于 Transformer 的语言模型面临的一项主要挑战（Vaswani 等，2017；Deletang 等，2023；Zhang 等，2023）。即使对于更大的 Transformer，这个问题依然存在（Brown 等，2020；Furrer 等，2020）。更长的上下文可以让模型受益于更多上下文学习示例、更多推理步骤，或更长的文本生成。然而，使用更长上下文训练 Transformer 可能极为缓慢，而且需要大量内存。在近期基于指令遵循数据集微调模型的范式中，这一点更加突出（Wei 等，2022a；Chung 等，2022；Ouyang 等，2022）。既不可能在所有可能的上下文长度上训练模型，而且随着序列长度增加，训练样本数量会急剧下降，这就要求模型能够从有限且较短的训练样本中泛化。在本工作中，我们关注在各种任务上从头训练的“仅解码器”Transformer 中，位置编码对长度泛化的影响。图 1 总结了我们的发现：不使用位置编码优于使用显式位置编码。

位置编码（PE）似乎是影响 Transformer 长度泛化的主要因素，因为模型必须系统地编码所有可能位置上的 token。最初的 Transformer 架构（Vaswani 等，2017）使用非参数化周期函数，以系统的方式表示绝对位置 embeddings（APE），但后续研究表明，这些函数不足以实现长度泛化（Ontanon 等，2022）。普遍观点认为，相对 PE（Shaw 等，2018；Raffel 等，2020）在长度泛化方面比 APE 的各种变体更有效（Ontanon 等，2022；Csordás 等，2021）。然而，Press 等（2022）表明，即使采用 Rotary（Su 等，2021）等相对 PE 的 Transformer，长度泛化表现也可能很差。不过，PE 的评估通常依赖语言建模困惑度这一关键指标（Haviv 等，2022；Press 等，2022），它并不总能与下游任务表现一致（Tay 等，2022）。这就引出了重要问题：位置编码究竟如何影响下游任务中的长度泛化？此外，早期实证证据表明，不使用显式位置信息的仅解码器 Transformer（Tsai 等，2019；Haviv 等，2022）在分布内设定下，可以达到与现有 PE 相同的表现，但它对长度泛化和下游表现的影响尚不明确。

最近，让模型把中间计算步骤输出到 scratchpad 中（也称为 chain-of-thought），已被用于改善 Transformer 的长度外推（Nye 等，2021；Wei 等，2022b）。这些技术独立于模型架构，可以与任何 PE 方法结合使用。然而，这些技术是否会使 PE 的选择变得无关紧要，至少在长度泛化方面如此，仍是一个开放问题；尤其是模型表现对 scratchpad 格式高度敏感（Bueno 等，2022；Akyurek 和 Akyurek，2022）。

为回答这些问题，我们对仅解码器 Transformer 的长度泛化开展了系统研究。这类架构因 GPT 模型家族（Radford 等，2019）而广为流行。我们使用最常见的位置编码方案，分别研究使用和不使用 scratchpad 的情况。具体而言，我们在一系列推理与数学任务上评估 APE（Vaswani 等，2017）、T5 的相对 PE（Raffel 等，2020）、ALiBi（Press 等，2022）、Rotary（Su 等，2021）以及不使用位置编码（NoPE）。结果表明：

  • 包括 ALiBi、Rotary 和 APE 在内的大多数常用位置编码方法不适合下游任务中的长度泛化，其表现不如 T5 的相对 PE。
  • 不使用位置编码的 Transformer（NoPE）优于所有显式位置编码方案。与显式 PE 相比，它们无需在 attention 机制中计算额外项就能做到这一点。
  • 我们表明，NoPE 在理论上能够表示绝对和相对两种 PE。但实证上，它更接近类似 T5 相对 PE 的相对编码方案。
  • Scratchpad 并不总有助于长度泛化，其格式会对表现产生很大影响。Attention 分布表明，NoPE 和 T5 的相对 PE 鼓励同时关注远距离和近距离位置，ALiBi 鼓励关注近期位置，而 Rotary 和 APE 不偏好特定位置。

2　背景：Transformer 中的位置编码

与 RNN 等序列模型相比，Transformer 是一种并行架构，它使用位置编码帮助编码词序。最常见的位置编码选择分为绝对式和相对式：前者直接表示每个绝对位置（例如 1、2、3……），后者使用 token 之间的距离作为位置信息。本节简要回顾 Transformer 中流行的编码方法（更正式的细节见附录 B）。

绝对位置 embedding（APE）将每个绝对位置 \(i\) 嵌入为位置向量 \(p_i\)，并在输入模型之前，将词 embeddings 与对应的 \(p_i\) 相加。APE 的非参数化变体使用正弦和余弦等周期函数，为任意位置 \(i\) 生成 embeddings（Vaswani 等，2017）。另一方面，GPT3（Brown 等，2020）和 OPT（Zhang 等，2022）使用的可学习 APE 将位置 embeddings 与模型参数一起训练；它无法为未见过的位置生成位置 embedding，因此上下文窗口被设置为固定长度。

T5 的相对偏置首先将位置 \(i\) 和 \(j\) 上 token 的相对距离 \((i-j)\) 映射为标量偏置值 \(b=f(i-j)\)，其中 \(f\) 是查找表。随后，将在训练过程中学到的相对偏置 \(b\) 加到 self-attention 机制中 query 和 key 的点积上。该查找表将超过某个阈值的距离映射到同一个参数，以便泛化到未见过的距离。

Rotary 被用于 PaLM（Chowdhery 等，2022）和 LLaMA（Touvron 等，2023）。它在执行点积 attention 之前，以与绝对位置成正比的角度旋转 query 和 key 的表示。这种旋转使 attention 点积仅依赖 token 之间的相对距离，因此它实际上属于相对位置编码（Su 等，2021）。

ALiBi 被用于 BLOOM（Scao 等，2022a），它与 T5 的相对偏置类似，但从 attention 分数中减去一个标量偏置。这个偏置随 query 和 key token 之间的距离线性增长。这实际上产生了对近期 token 的偏好，即近因偏置。

注意，BERT 等仅编码器 Transformer 在缺少位置编码时会变成词袋模型。然而，带有因果 attention 掩码的仅解码器 Transformer 并不具有置换不变性，即使没有显式位置信息，也可以对序列建模（Tsai 等，2019）。但这些模型是否隐式编码位置信息，或者能否泛化到未见过的长度，尚不清楚。我们将在第 5 节揭示这一点。

3　模型评估

长度泛化设定。遵循 Anil 等（2022），我们关注复制、加法等算法任务。对于每个任务，我们使用一定长度以内的有限数量样本进行训练，并在推理时同时测试见过和未见过的长度。我们将这些问题表述为序列到序列任务：输入序列是问题实例，输出序列是解答。形式上，令 \(\mathcal D=\{(x_i,y_i)\}\) 表示某个此类任务的数据集，其中 \(x_i\) 是输入，\(y_i\) 是输出序列。对于每个任务，可以定义一个函数 \(\lambda:\mathcal D\to\mathbb N\)，返回任务实例 \(d\in\mathcal D\) 所属的长度桶。这可以是 token 数，也可以是任何一般意义上的长度或推理深度。使用该函数和阈值 \(L\)，我们用 \(\lambda\le L\) 的样本学习任务，用 \(\lambda>L\) 的样本评估泛化。每个实例的表现报告为其答案与真实答案完全匹配的准确率。

架构。我们使用常规的仅解码器 Transformer 架构作为所有实验的基础，并考虑不同的位置编码方法：绝对位置 embedding（APE）、ALiBi、Rotary 和 T5 的相对偏置。我们还考虑移除位置编码（NoPE），以更好地理解它在长度泛化中的作用。注意，我们使用基于正弦函数的 APE（Vaswani 等，2017），因为可学习的变体无法为未见过的位置生成 embeddings。由于没有公开可用的、在相同预训练数据上采用上述不同 PE 训练的 Transformer 语言模型，我们选择针对每个任务，使用其训练数据和自回归语言建模目标，从头训练模型：

\[\log p_\theta(y\mid x)=\sum_{t=1}^{T}\log p_\theta(y_t\mid x,y_{1:t-1}).\]

5　NoPE 如何表示位置？

NoPE 模型出人意料的表现说明，它捕获了有用且能够泛化的位置信息。但关键问题是，它如何做到这一点。接下来的两节将从理论和实证两个角度分析这一问题。

5.1　NoPE 在理论上能够表示绝对和相对两种 PE

令 \(f_\theta\) 为一个 NoPE 仅解码器 Transformer 模型，其中 \(\theta\) 表示模型参数。\(f_\theta\) 通过依次应用一系列层来处理输入序列 \(x=[\texttt{<bos>},x_1,\ldots,x_T]\)。注意，由于 \(f_\theta\) 没有任何 PE，输入 \(x\) 不会被加入位置信息（例如 \([1,2,\ldots,T]\)）。每层 \(l\) 包含 self-attention 头和一个前馈子层，读取前一层的隐藏状态 \(H^{(l-1)}\)，并产生第 \(l\) 层的隐藏状态 \(H^l\)。每个头由 query 矩阵 \(W_Q\)、key 矩阵 \(W_K\)、value 矩阵 \(W_V\) 和输出矩阵 \(W_O\) 参数化，其中 \(W_Q,W_K,W_V\in\mathbb R^{h\times d}\)，\(W_O\in\mathbb R^{d\times h}\)。\(d\) 和 \(h\) 分别是模型隐藏状态大小和 attention 维度。\(W_1,W_2\in\mathbb R^{d\times k\cdot d}\) 是前馈子层的权重矩阵。

5.2　NoPE 在实践中学会使用相对 PE

为探索 NoPE 在实践中采用的机制，我们进行定量分析，将其 attention 模式与采用不同位置编码技术训练的模型进行比较。假设是：如果 NoPE 使用了与其他 PE 相似的算法，那么这些模型的 attention 模式应当十分相近。

6　Scratchpad 会使位置编码的选择变得无关紧要吗？

在 scratchpad / CoT 提示中，模型将得到最终答案所需的中间计算显式生成为输出的一部分。这类机制实际上为中间值提供了直接的分解与存储方式；已有研究表明，即使模型规模较小，也能改善 Transformer 的长度泛化（Nye 等，2021）。由于 scratchpad 只改变模型的输入和输出，而不改变架构，因此，在存在 scratchpad 时，位置编码等架构选择如何影响长度泛化，仍不清楚，也尚未得到研究。为回答这一问题，我们在数学与推理任务组中，分别使用和不使用 scratchpad 训练所有 PE，并比较其表现。

此外，如何在 scratchpad 中表示中间计算，即 scratchpad 格式，是一个重要设计选择，会对模型表现产生不可忽视的影响（Bueno 等，2022）。

7　讨论

在开展昂贵的预训练之前，实践者必须对 Transformer 架构中的细节（例如位置编码）作出重要选择。在 PE 的 I.I.D. 评估中，我们发现不同 PE 的表现相近，与 Haviv 等（2022）和 Scao 等（2022b）的观察一致，这使得最佳位置编码的选择颇具挑战。

本文使用下游任务中的长度泛化作为评估位置编码表达能力的手段。与 I.I.D. 评估相比，我们的设定揭示了不同位置编码方法之间的明显差异。我们发现，NoPE 优于显式 PE，而在显式 PE 中，常用方法落后于 T5 的相对 PE。事实上，近期发布的 LLM（Touvron 等，2023；Chowdhery 等，2022）表明，Transformer 架构正出现用 Rotary 取代 APE 的趋势。然而，第 4 节结果清楚地表明，在长度泛化上，Rotary 仅略优于 APE。此外，第 6.1 节表明，它的行为与 APE 相似，说明它可能也容易受到相同局限的影响。

显式 PE 在长度外推方面相对于 NoPE 的劣势，为“位置编码给 Transformer 带来挑战”这一观点补充了越来越多的证据（Sinha 等，2022；Luo 等，2021）。我们的实证结果和理论分析表明，移除位置编码有望成为对广泛使用的仅解码器 Transformer 架构的一项有效修改。

困惑度与下游表现。由于人类的认知限制（Gibson，1998；Kiyono 等，2021），语言建模数据可能包含近距离依赖。这种自然存在的结构（在互联网语料中可能十分丰富）与 ALiBi 等位置编码固有的近因偏置相结合，可能使模型的长度泛化表现呈现不切实际的景象。事实上，Chi 等（2023）近期证明，使用窗口 attention 掩码，即屏蔽距离超过窗口大小 \(w\) 的 token，就能复现 ALiBi 的长度泛化表现。有趣的是，我们也观察到，T5 的相对 PE 可以视为 ALiBi 的可训练版本，却学会同时关注远距离和近距离依赖（图 F.3）。这与 Tay 等（2022）的观察一致，也凸显了在下游任务上设置评估、而非只依赖困惑度的重要性。

8　相关工作

Transformer 中的长度泛化失败。长度泛化问题长期以来一直是神经序列模型研究中的一个关注点（Graves 等，2016；Kaiser 和 Sutskever，2016；Lake 和 Baroni，2018；Hupkes 等，2020；Yehudai 等，2021）。作为最先进的序列模型，Transformer 也不例外。一组研究表明，采用 APE 的常规 Transformer 在 PCFG（Hupkes 等，2020）、LEGO（Zhang 等，2023）或 CLUTRR（Sinha 等，2019；Gontier 等，2020）等特定数据集上存在泛化失败。即使在 T5（Furrer 等，2020）和 LaMDA（Anil 等，2022）等预训练 Transformer 中，也报告过长度泛化问题。Csordás 等（2021）和 Ontanon 等（2022）研究了位置编码对长度泛化的影响，但主要关注证明相对 PE 优于 APE。另一方面，Press 等（2022）提出一种新编码方法 ALiBi，并证明它在外推上优于常用 PE，但仅限于人类语言建模场景。最相关的是 Deletang 等（2023）近期对各种神经序列模型（包括 RNN 和堆叠 RNN）在乔姆斯基层级任务上的长度泛化研究。然而，他们并未聚焦位置编码之间的差异，也未聚焦自回归模型。与这些研究不同，我们针对广泛任务全面比较常用 PE 的长度泛化，并专门关注代表许多当代 LLM 的自回归模型。

位置编码。Transformer 的一个核心组成部分是位置编码机制，它帮助模型表示输入序列的顺序。Transformer 编码器中的 self-attention 机制对顺序具有不变性，需要 PE 才能避免退化为词袋模型。为此，人们提出了许多方法。最初，Vaswani 等（2017）引入了基于正弦函数的绝对位置编码（其可学习变体由 Devlin 等，2019 推广）。随后 Shaw 等（2018）进一步提出对位置信息进行相对编码的方法，推动了 TransformerXL（Dai 等，2019）和 T5（Raffel 等，2020）等采用相对编码、且具有良好长度泛化表现的预训练语言模型的发展。最近，Su 等（2021）借鉴正弦函数，提出在应用 self-attention 之前旋转隐藏表示，以新的方式编码位置信息。这种称为 Rotary 的方法已成为近期 LLM 的热门选择。Press 等（2022）简化了 T5 的相对编码，提出更高效的变体 ALiBi，同时保持或改善外推表现。由于具有因果 attention 掩码，仅解码器 Transformer 并非对顺序无感，因此可以在没有显式位置信息的情况下工作。

9　结论

我们研究了仅解码器 Transformer 中，不同位置编码在各种下游数学与推理任务上的长度泛化稳健性。广泛的实证研究表明了 NoPE 的有效性，并进一步证明，广泛使用的显式 PE 不适合长度泛化。我们还证明，NoPE 可以隐式学习绝对和相对两种位置，但在实践中使用后者。最后，我们发现 scratchpad 的有效性取决于任务，并不是解决长度泛化问题的可靠方案。

局限性

本工作主要将位置编码视为 Transformer 解码器架构的一项设计选择。由于没有公开可用的、在相似条件下采用不同 PE 训练的大语言模型，我们未能研究大规模预训练如何影响不同 PE。由于计算预算有限，我们将其留待未来工作。

B　背景

B.1　预备知识

本节建立基础，并介绍全文使用的记号。附录 C.1 和 C.2 将引用这些内容。

令 \(f_\theta\) 为仅解码器 Transformer 模型，其中 \(\theta\) 表示全部模型参数。\(f_\theta\) 通过依次应用一系列 Transformer 层，处理输入序列 \(x=[x_0,x_1,\ldots,x_T]\)，并将其映射为输出序列 \(y=[y_0,y_1,\ldots,y_T]\)。注意，仅解码器意味着每层的 attention 机制都是因果的，即 attention 权重只基于先前位置计算。

层 \(\operatorname{TLayer}^{(l)}(H^{(l-1)};\theta_l)\) 包含 self-attention 头和一个前馈子层，读取前一层隐藏状态 \(H^{(l-1)}\)，产生第 \(l\) 层的隐藏状态 \(H^l\)；其中 \(l\) 是层索引，\(\theta_l\) 是第 \(l\) 层的参数集合。每个隐藏状态 \(H^{(l)}\in\mathbb R^{d\times(T+1)}\) 都是一个矩阵，其第 \(t\) 列记为 \(h_t^{(l)}\)，表示位置 \(t\) 的隐藏状态。

第 \(l\) 层由参数集合 \(\theta_l=\{(W_Q^m,W_K^m,W_V^m,W_O^m)_m,W_1,W_2\}\) 参数化，其中 \(W_Q^m,W_K^m,W_V^m\in\mathbb R^{h\times d}\)，\(W_O^m\in\mathbb R^{d\times h}\)，分别是第 \(m\) 个头的 query、key、value 和输出矩阵。\(W_1,W_2\in\mathbb R^{d\times k\cdot d}\) 是前馈子层的权重矩阵。\(d\) 表示模型隐藏状态大小，\(h\) 为 attention 维度（\(h=d/\text{头数}\)），\(k\) 是前馈子层中隐藏状态大小的倍数（常见 Transformer 实现通常设为 4）。注意，当上下文明确时，我们省略层索引 \(l\) 和 attention 头索引 \(m\)。

Transformer 层 \(\operatorname{TLayer}^{(l)}\) 独立并行地处理 \(H^{(l-1)}\) 的各列，得到输出。\(H^{(l)}\) 第 \(t\) 列的计算如下：

\[h_t^{(l)}=\operatorname{FF}\!\left(\lambda(a_t+h_t^{(l-1)})\right)+a_t+h_t^{(l-1)}.\tag{3}\]

其中，\(\operatorname{FF}\) 为前馈子层，\(\lambda\) 为层归一化，\(a_t\in\mathbb R^d\) 为位置 \(t\) 上多头 self-attention 子层的输出。具体来说，\(a_t\) 计算为：

\[a_t=\sum_m\operatorname{Attn}^{(m)}\!\left(h_t^{(l-1)},H^{(l-1)}\right).\tag{4}\]

\[o_t=W_O\left(\sum_{i\le t}\hat\alpha_i v_i\right).\tag{5}\]

其中，\(\hat\alpha=\operatorname{softmax}(\alpha)\in\mathbb R^{(t+1)}\)，\(\alpha\) 是 attention 权重向量：

\[\alpha=[\langle q_t,k_0\rangle,\langle q_t,k_1\rangle,\ldots,\langle q_t,k_t\rangle]^\top.\tag{6}\]

前馈子层 \(\operatorname{FF}(\cdot)\in\mathbb R^d\) 是一个两层 MLP：

\[\operatorname{FF}(x)=W_2\sigma(W_1^\top x).\tag{7}\]

其中，\(\sigma\) 为非线性激活函数（通常为 ReLU 或 GeLU（Hendrycks 和 Gimpel，2020））。此外，\(\lambda(\cdot)\in\mathbb R^d\) 是层归一化（Ba 等，2016）。注意，在式（4）中，我们采用 attention 头的加法视角（Elhage 等，2021），而非拼接后相乘的视角（Vaswani 等，2017），因为前者更易理解和分析。但二者在数学上等价（Elhage 等，2021）。

隐藏状态使用输入序列的可学习 embedding 初始化：\(H^{(0)}=W_EX\)，其中 \(W_E\in\mathbb R^{d\times V}\) 为 embedding 矩阵，\(X\in\mathbb R^{V\times(T+1)}\) 为经过 one-hot 编码的输入序列。\(V\) 是词表大小。

B.2　位置编码

几乎所有位置编码方法，都可以根据其如何实现式（6）中的点积运算来解释和形式化。因此，本节说明不同位置编码方案如何实现点积 \(\langle q_t,k_i\rangle\)。

绝对位置编码（APE）。APE 为每个绝对位置 \(i\) 分配位置向量 \(p_i\)，并在输入模型前将其与词 embeddings 结合。因此，APE 首先修改隐藏状态的初始化方式：

\[H^{(0)}=W_EX+W_PP.\tag{8}\]

其中，\(W_P\in\mathbb R^{d\times T}\) 为位置 embedding 矩阵，\(P\in\mathbb R^{V_p\times(T+1)}\) 为经过 one-hot 编码的绝对位置序列。\(V_p\) 为最大绝对位置。因此，第 \(j\) 列的隐藏状态为：

\[h_j^{(0)}=e_j+p_j.\tag{9}\]

F.3　泛化评估

我们的评估旨在考察：随着上下文长度变化，尤其是在超过训练上下文长度时，模型预测给定 token 的表现如何变化。理想情况下，随着上下文长度增加，模型可获得更多信息，因此我们预期困惑度总体上应有所改善。在本实验中，我们选取 1500 个验证文档作为样本，每个文档对应一个源代码文件。对于每个文档，我们在 512 至 2560 的不同上下文长度下，计算末尾 token 的困惑度（注意，模型本身使用 1024 的上下文长度预训练）。这种方式使我们能够在分布内和分布外两种条件下评估模型困惑度。为使计算量和推理次数可控，我们最多测量文档末尾 200 个 token 的困惑度，并确保在每种上下文长度下评估的 token 集合完全相同。
