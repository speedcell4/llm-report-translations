模型介绍

Hy3 是由腾讯混元团队研发的混合专家（MoE）模型，总参数量为 295B，激活参数量为 21B，MTP 层参数量为 3.8B。4 月底推出 Hy3 Preview 后，我们收集了 50 多个产品的反馈，并使用更高质量的数据扩大后训练规模。今天，我们推出 Hy3；它优于同等规模的模型，并可比肩参数量为其 2–5 倍的旗舰开源模型。它在各类产品与生产力任务中的实用性也得到显著提升。

更强大的 agent 能力

在 Hy3 Preview 的基础上，我们进一步提升后训练数据的质量与多样性，同时扩大 RL 训练规模。Hy3 在推理、agent 和长上下文任务上取得扎实进步，能够与规模大得多的旗舰模型竞争。

在编程、办公、金融建模、前端设计与游戏开发等生产力场景中，Hy3 取得显著进步，如今可以成为可靠且具成本效益的模型选择。

我们认为，公开基准分数无法反映全部情况。因此，我们组织了 270 位专家，使用他们实际工作中的任务开展盲测。Hy3 的得分为 2.67/4，优于 GLM-5.1 的 2.51/4；其优势在前端开发、数据与存储、CI/CD 任务中最为明显。

更可靠的产品体验

基准无法完整衡量模型的实用性。根据广泛的产品反馈，我们识别并修复了以下问题，获得了产品团队持续的积极反馈。

工具调用与输出格式的稳定性：我们修复了多项基础可靠性问题，使模型在各种工具配置与输出约束下达到生产级标准。工具调用的错误恢复能力与整体效率得到提升。Hy3 还能够泛化到不同的 agent 执行框架。在 SWE-Bench Verified 上，CodeBuddy、Cline、KiloCode 等执行框架之间的准确率波动保持在 4% 以内。

知识与抗幻觉能力：遵循“有依据时回答，缺少证据时明确说明，不混淆来源或编造数据”的目标，我们实施了细粒度的数据清洗与训练约束。在基于真实场景的内部评测中，Hy3 的幻觉率从 12.5% 降至 5.4%，常识错误率从 25.4% 降至 12.7%。这些变化显著减少了事实混淆、编造与逻辑矛盾。

复杂上下文保持与多轮意图跟踪：通过联合优化 SFT 与 RL，Hy3 改善了指代消解、省略还原和多轮约束继承等实际使用中的痛点。在内部多轮综合测试中，问题率从 17.4% 降至 7.9%。Hy3 在 MRCR 等长对话评测上也取得明显进步。其输出更为简洁，同时确保复杂意图在长程交互中不会衰减或偏移。

快速开始

建议先通过 vLLM 或 SGLang 部署服务，然后通过 OpenAI 兼容 API 调用：

from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="EMPTY")

response = client.chat.completions.create(
    model="hy3",
    messages=[
        {"role": "user", "content": "Hello! Can you briefly introduce yourself?"},
    ],
    temperature=0.9,
    top_p=1.0,
    # reasoning_effort: "no_think" (default, direct response), "low", "high" (deep chain-of-thought)
    extra_body={"chat_template_kwargs": {"reasoning_effort": "no_think"}},
)
print(response.choices[0].message.content)

推荐参数：temperature=0.9，top_p=1.0。

推理模式：复杂任务（数学、编程、推理）建议设置 reasoning_effort="high"，日常对话可使用默认的 "no_think" 直接回复。

具体部署方式请参考下方推理和部署章节。

推理和部署

Hy3 总参数量为 295B，当使用 8 张 GPU 时，建议使用 H20-3e 或其他有更大显存的卡型。

对于生产环境部署，我们建议使用 vLLM 或 SGLang，这两个框架都为 Hy3 提供了专门的配置方案：

  • vLLM - 请查阅 vLLM recipes

  • SGLang - 请查阅 SGLang cookbook

vLLM

从源码构建 vLLM：

uv venv --python 3.12 --seed --managed-python
source .venv/bin/activate
git clone https://github.com/vllm-project/vllm.git
cd vllm
uv pip install --editable . --torch-backend=auto

启动 vLLM 服务，开启 MTP：

# Switch to trtllm backend to work-around mnnvl workspace size issue.
export VLLM_FLASHINFER_ALLREDUCE_BACKEND=trtllm
vllm serve tencent/Hy3 \
  --tensor-parallel-size 8 \
  --speculative-config.method mtp \
  --speculative-config.num_speculative_tokens 2 \
  --tool-call-parser hy_v3 \
  --reasoning-parser hy_v3 \
  --enable-auto-tool-choice \
  --port 8000 \
  --served-model-name hy3

SGLang

从源码构建 SGLang：

git clone https://github.com/sgl-project/sglang
cd sglang
pip3 install pip --upgrade
pip3 install "transformers>=5.6.0"
pip3 install -e "python"

启动 SGLang 服务，开启 MTP：

python3 -m sglang.launch_server \
  --model tencent/Hy3 \
  --tp-size 8 \
  --tool-call-parser hunyuan \
  --reasoning-parser hunyuan \
  --speculative-num-steps 2 \
  --speculative-eagle-topk 1 \
  --speculative-num-draft-tokens 3 \
  --speculative-algorithm EAGLE \
  --port 8000 \
  --served-model-name hy3

强化学习训练

Hy3 支持基于 verl 的 GRPO 强化学习训练，训练侧使用 Megatron-LM（通过 NVIDIA Megatron-Bridge 完成模型转换），rollout 侧使用 vLLM。详细文档请参考：强化学习训练指南
