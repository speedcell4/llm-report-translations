摘要

大语言模型（LLM）已成为具有长流式输入的现实应用（例如由 LLM 驱动的智能体）的基石。然而，现有 LLM 在最大长度受限的序列上进行预训练，由于分布外问题和注意力分散问题，无法处理更长的序列。常见解决方案通常涉及在更长序列上进行持续预训练，这会引入昂贵的计算开销，以及模型能力不可控的变化。本文揭示了 LLM 无需任何微调即可理解超长序列的内在能力。为此，我们提出一种基于记忆的免训练方法 InfLLM。具体而言，InfLLM 将远距离上下文存储到额外的记忆单元中，并采用高效机制查找与 token 相关的单元，用于注意力计算。因此，InfLLM 使 LLM 能够以有限的上下文窗口高效处理长序列，并充分捕获长距离依赖。无需任何训练，InfLLM 就能让在几千个 token 组成的序列上预训练的 LLM，取得与在长序列上持续训练这些 LLM 的有竞争力的基线相当的性能。即使将序列长度扩展到 1,024K，InfLLM 仍能有效捕获长距离依赖。我们的代码见 https://github.com/thunlp/InfLLM。

1　引言

近期，大语言模型（LLM）在各种任务中取得了显著成果（Brown et al., 2020; Bommasani et al., 2021; Han et al., 2021; Touvron et al., 2023; Meta, 2024）。它们遵循复杂指令的能力为实现通用人工智能带来了希望（OpenAI, 2023; Ouyang et al., 2022）。随着 LLM 驱动的应用蓬勃发展，例如智能体构建（Park et al., 2023; Qian et al., 2023; Wang et al., 2024a）和具身机器人（Driess et al., 2023; Liang et al., 2023），增强 LLM 处理流式长序列的能力变得越来越关键。例如，LLM 驱动的智能体需要基于全部历史记忆，处理从外部环境持续接收的信息，因此必须具备强大的流式长序列处理能力。

由于未见过的长输入所带来的限制（Han et al., 2023），以及包含噪声的上下文造成的注意力分散（Liu et al., 2023; Tworkowski et al., 2023），大多数仅在几千个 token 组成的序列上预训练的 LLM 无法处理更长序列（Press et al., 2022; Zhao et al., 2023）。常见解决方案通常是在更长序列上持续训练 LLM，但这又会导致高昂成本，并需要大规模、高质量的长序列数据集（Xiong et al., 2023; Li et al., 2023）。而在更长序列上的持续训练过程，还可能削弱 LLM 在短上下文上的性能（接原文第 2 页）。

本文提出一种基于记忆的免训练方法 InfLLM，以有限的计算成本对超长序列进行流式处理。具体而言，InfLLM 将滑动窗口注意力（Xiao et al., 2023; Han et al., 2023）与高效的上下文记忆相结合，使每个 token 仅关注局部上下文以及记忆中的相关上下文。考虑到注意力分数矩阵的稀疏性，处理每个 token 通常只需要其上下文的一小部分（Zhang et al., 2023b），其余无关上下文会成为噪声，导致注意力分散问题（Tworkowski et al., 2023）。因此，我们构建了包含远距离上下文信息的外部记忆。每个计算步骤仅选择记忆中的相关信息，而忽略其他无关噪声。借助这一机制，LLM 可以使用有限大小的窗口理解整个长序列，并避开包含噪声的上下文。

长序列中大量带噪声的上下文 token，对记忆查找的有效性和效率构成了重大挑战。为应对这些挑战，我们设计了块级上下文记忆机制。具体而言，InfLLM 将过去的键值向量组织成块，每个块包含一段连续的 token 序列。在每个块中，选择获得最高注意力分数、语义上最重要的 token 作为单元表示，用于随后记忆查找中的相关性计算。这一设计主要带来两项好处：（1）有效查找：与单个 token 相比，每个块连贯的语义能够更有效地满足相关信息检索的需求。单元表示的选择最大限度地减少了不重要 token 对相关性计算的干扰，提高了记忆查找的整体命中率。（2）高效查找：块级记忆单元消除了逐 token 计算相关性的需要，大幅降低计算成本。此外，块级单元确保了连续的内存访问，从而最大限度地降低记忆加载成本，提高计算效率。进一步考虑到大多数单元使用频率较低，InfLLM 将所有单元卸载到 CPU 内存中，并在 GPU 显存中动态保留经常使用的单元，显著减少 GPU 显存占用。值得注意的是，InfLLM 中的块级记忆机制不涉及任何额外训练，可以直接应用于任何 LLM。

为评估 InfLLM 的有效性，我们采用 Mistral-7B-inst-v0.2（Jiang et al., 2023）和 Llama-3-8B-Instruct（Meta, 2024）作为基础模型，它们分别在不超过 32K 和 8K 个 token 的序列上进行预训练。我们使用两个广泛采用的基准 ∞-Bench（Zhang et al., 2023a）和 Longbench（Bai et al., 2023）进行评估。尤其是 ∞-Bench 的平均序列长度超过 100K 个 token，对大多数现有 LLM 都具有挑战性。与在更长序列上持续训练 LLM 的典型方法相比，实验结果表明，InfLLM 可以让在几千个 token 组成的序列上预训练的 LLM，在无需任何额外训练的情况下取得相当的性能。此外，我们在包含 1,024K 个 token 的序列上测试 InfLLM，它仍能有效捕获长距离依赖，展示了在长流式输入场景中的潜力。

2　相关工作

让 LLM 处理长序列已得到广泛研究（Dong et al., 2023; Tay et al., 2023; Huang et al., 2023），一般可分为两类主要方法：上下文长度外推和高效上下文计算。前者旨在让在短序列上训练的 LLM 处理远长于训练序列的序列。后者聚焦于提高注意力层的计算效率，使从头预训练能够处理更长序列的 LLM 更加高效。尽管本文重点是上下文长度外推，我们也详细介绍高效上下文计算，并介绍基于记忆的模型的相关工作。

上下文长度外推。由于计算和内存需求较高，LLM 的训练通常局限于短序列。直接将 LLM 应用于长序列，会面临由长输入和带噪声输入引起的分布外与注意力分散挑战（Han et al., 2023; Tworkowski et al., 2023）。因此，上下文长度外推作为一种无需额外训练即可增加 LLM 序列长度的方法，受到了关注。最早的方法涉及在预训练期间设计新的相对位置编码机制（接原文第 3 页）。

高效上下文计算。注意力层的二次计算复杂度是限制 LLM 长序列处理能力的主要因素。因此，许多研究者致力于设计高效注意力机制，包括使用稀疏注意力（Zaheer et al., 2020; Beltagy et al., 2020; Child et al., 2019; Ainslie et al., 2020; Zhao et al., 2019）、使用核函数近似注意力计算（Kitaev et al., 2020; Wang et al., 2020; Katharopoulos et al., 2020），以及用线性复杂度的状态空间模型替代注意力层（Gu et al., 2022; Gu & Dao, 2023）。这些方法需要修改模型架构，因此需要重新训练模型。同时，许多研究者通过驱逐无用的键值向量来减少计算，提高推理效率（Zhang et al., 2023b; Li et al., 2024; Ge et al., 2023）。由于未见过的位置引起的分布外问题，这些方法无法在不进一步训练的情况下外推 LLM 的上下文窗口。

基于记忆的模型。记忆网络已被研究了数十年，并已被证明能够有效地为模型提供额外知识和信息存储能力（Graves et al., 2014; Weston et al., 2015; Sukhbaatar et al., 2015; Miller et al., 2016）。随着预训练模型的成功，记忆层也逐步应用于循环 transformer 层的训练过程，使模型能够递归地处理长序列（Dai et al., 2019; Rae et al., 2020; Khandelwal et al., 2020; Wu et al., 2022; Bertsch et al., 2023; Munkhdalai et al., 2024）。这些工作将序列分段，分别编码每一段，并用记忆存储前面各段的上下文信息。虽然这些方法在概念上与 InfLLM 相似，但它们涉及模型架构修改，并需要进一步训练整个模型。相比之下，我们旨在探索 LLM 的内在特性，提出用于长文本理解的免训练记忆模块。

3.1　整体框架

3.2　上下文记忆

已有研究表明，LLM 的注意力分数矩阵是稀疏的，仅保留一小部分键值向量就能够生成相同输出（Zhang et al., 2023b）。受此启发，我们设计上下文记忆，从大量被驱逐的 token 中高效查找相关上下文，并忽略无关上下文以节省计算成本。最直观的方法，是针对每个过去的键值向量、每个注意力头分别构建 token 级记忆单元；但这会产生海量记忆单元，以及不可接受的计算成本和非连续内存访问成本。因此，考虑到长序列局部语义的连贯性，我们将过去的键值向量分成块，每个块作为一个记忆单元，并在块级进行记忆查找，在保持性能的同时降低成本。

位置编码。现有 LLM 训练通常使用数量有限的位置编码，直接将其应用于更长序列的处理时，会遇到分布外挑战（Han et al., 2023）。此外，在 InfLLM 中，当前键值缓存由一些不连续的文本块组成，直接给它们分配连续位置编码也会导致不匹配，使模型困惑。因此，受已有工作启发（Raffel et al., 2020; Su, 2023），我们为所有超出局部窗口大小的 token 分配相同的位置编码。具体而言，上下文记忆单元中的 token 与当前 token 之间的距离被设为 lL。

缓存管理。为使 LLM 能够处理超长序列流，同时捕获长上下文中的语义相关性，我们需要保留全部记忆单元，并在每个计算步骤查找它们。考虑到大多数单元很少使用，我们采用卸载机制，将大多数记忆单元存储在 CPU 内存中，仅在 GPU 显存中保留代表性 token 和当前步骤需要的记忆单元。此外，考虑到长序列的语义连贯性，即相邻 token 通常需要类似的记忆单元，我们在 GPU 显存中分配缓存空间，并采用最近最少使用策略管理。该方法使得在有限 GPU 显存下高效编码超长序列成为可能。观察表明，我们的卸载机制让 InfLLM 只需 26G 显存即可处理包含 100K 个 token 的序列。此外，GPU 缓存未命中率很低，这意味着卸载机制在节省 GPU 显存的同时，不会在记忆加载中引入显著的时间开销。详情见附录。

进一步，对于超长序列，每个单元的代表性 token 也可以卸载到 CPU 内存中，构建高效的 k 近邻索引，从而进一步降低计算复杂度。

更广泛的影响

本文工作的目标是推进大语言模型长序列处理领域的发展。我们的工作可能带来许多社会影响，但我们认为没有哪一项必须在此特别强调。

局限性

本文提出 InfLLM，一种无需额外训练即可扩展 LLM 上下文窗口的方法。我们使用广泛采用的长文本评估基准 ∞-Bench 验证模型的有效性。然而，我们的方法仍有以下局限：（1）我们在 CPU 内存中存储大量过去的键值（KV）缓存，增加了 CPU 内存使用量。未来可以通过结合 KV 缓存量化等技术，降低 CPU 内存需求。（2）尽管 InfLLM 减少了 LLM 处理长文本的计算开销，但仍有加速空间。未来可以将 InfLLM 与 llama.cpp4 和 vllm（Kwon et al., 2023）等推理框架结合，进一步提高推理速度。

A　缓存管理策略

由于超长序列具有海量记忆单元，我们采用卸载机制以节省 GPU 显存。考虑到记忆单元使用频率较低，我们将大多数记忆单元卸载到 CPU 内存，仅在 GPU 显存中保留经常使用的记忆单元和当前所需的记忆单元。为此，我们在 GPU 显存中维护缓存，以有效利用 GPU 显存，并减少 CPU 与 GPU 之间的通信。GPU 缓存大小固定，因此我们设计最近最少使用（LRU）策略来管理缓存。本节将详细介绍该管理策略。

加载记忆单元。每个计算步骤，我们首先计算各记忆单元的相关性分数，以确定应当使用哪些单元。然后，对于每个所需记忆单元，先在缓存中查找；若未命中，再从 CPU 内存传输到 GPU 显存。

卸载记忆单元。注意力计算之后，我们需要卸载冗余记忆单元，以保持 GPU 缓存大小固定。为此，我们采用 LRU 策略。具体而言，对于每个加载到 GPU 缓存中的记忆单元，我们分配一个频率分数 sb，用于决定该单元应保留在 GPU 显存中，还是卸载至 CPU 内存以节省 GPU 显存。频率分数在注意力计算之后更新，具体更新方式如下：

我们也使用 LongBench（Bai et al., 2023）作为基准，评估 InfLLM 和基线模型的有效性。评估结果见表 5。结果表明：（1）在多种不同任务中，InfLLM 优于其他能够处理流式输入的模型。这证明，上下文记忆提供的上下文信息能够高效提高模型性能。（2）采用 Llama-3 作为基础模型时，StreamingLLM 和 LM-Infinite 的性能仅与原始 Llama-3 相当，甚至更差。这表明，虽然滑动窗口注意力能够有效扩展 LLM 的上下文窗口大小，但这些模型丢弃了长距离上下文信息，因此无法有效理解长序列。（3）Mistral 可以处理最长 32K 的文本，覆盖 LongBench 中大多数样本。相比之下，InfLLM 的窗口大小仅为 12K，却在平均性能上取得相当甚至更好的结果。这进一步展示了 InfLLM 过滤长上下文中噪声的能力，从而实现更好的长序列理解。
