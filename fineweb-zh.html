摘要

LLM 的性能在很大程度上取决于其预训练数据集的质量和规模。然而，Llama 3 和 Mixtral 等最先进的开放 LLM 的预训练数据集并未公开，人们对这些数据集的创建方式知之甚少。在这项工作中，我们介绍 FineWeb：一个源自 96 个 Common Crawl 快照、包含 15 万亿 token 的数据集，与其他开放预训练数据集相比，它能够训练出性能更好的 LLM。为增进对如何以最佳方式构建高质量预训练数据集的理解，我们详细记录了 FineWeb 使用的所有设计选择，并进行了消融实验，包括深入研究去重和过滤策略。此外，我们介绍 FineWeb-Edu：从 FineWeb 中筛选出的、包含 1.3 万亿 token 的教育性文本集合。在 FineWeb-Edu 上预训练的 LLM 在 MMLU 和 ARC 等知识与推理密集型基准上表现显著更好。我们公开发布数据集的同时，也发布了数据整理代码库以及在消融实验中训练的所有模型。

1 引言

LLM 能够胜任多种基于文本的任务，因此迅速成为一种无处不在的技术。推动 LLM 成功的一个因素是模型规模持续增长 [1–3]，而这又需要越来越大的预训练数据集。除规模之外，预训练数据的其他特征也已被证明十分重要，包括过滤“低质量”内容 [2, 4] 和移除重复文本 [5]。最终，开发预训练数据集时的整理选择可能对 LLM 的下游能力和性能产生巨大影响。因此，预训练数据集的整理策略往往被视为严格保密的商业秘密。事实上，许多流行的“开放”语言模型虽然公开了参数，却没有发布预训练数据集，相关说明也极为有限 [6, 7]。缺乏对高质量大规模预训练数据集的访问，以及缺乏关于其整理过程的信息，使人们担忧专有知识与公共知识之间的差距正在扩大。

在这项工作中，我们希望通过开发并发布 FineWeb 数据集来缩小这一差距。这是一组可用于训练高性能 LLM 的大规模预训练数据集。具体而言，我们首先介绍 FineWeb，一个从 96 个 Common Crawl 快照获取文本、包含 15 万亿 token 的数据集。FineWeb 的规模足以训练参数超过 5000 亿、符合 Chinchilla 最优配置的模型 [1]。除了规模，FineWeb 的构建方案还采用了有原则的方法来选择和调节启发式过滤规则，从既有工作中的 50 多个候选过滤器中筛选出少量有效过滤器。此外，我们深入探索了不同去重策略和粒度如何影响性能。为验证我们的设计选择，我们最终证明，在 FineWeb 上训练的模型优于在其他……

2 背景

在这项工作中，我们关注基于自回归 Transformer 的 LLM 训练数据集的整理 [13]。LLM 的核心目标是在以过去的 token 为条件的情况下，生成下一个文本 token 的概率分布，每个 token 通常是一个词或子词单元 [3]。这一范式的通用性使 LLM 能够应用于几乎任何基于文本的任务：只需构造一个前缀，使其续写对应于执行该任务即可（例如，英译法任务中的“‘The cat sat on the mat’翻译成法语是……”）。这类模型可能经历多个训练阶段，包括在非结构化文本数据上预训练、通过微调提升特定任务的性能 [14]、通过多任务微调提升对新任务的泛化能力 [15]，以及从人类反馈中学习以提高指令遵循能力 [16, 2]。在这项工作中，我们仅关注预训练阶段的数据整理。

虽然人们考虑过多种预训练数据来源，包括书籍 [2, 3, 17, 4]、Wikipedia [2, 3, 17, 4] 和研究论文 [2, 4, 18] 的文本，但一种极为常见的选择是使用网页文本，即从公共互联网上的网页抓取的文本 [19, 20]。OpenAI [21] 和 Anthropic [22] 等公司会自行抓取网页，但设计、实现和运行大规模网页爬虫需要大量资源和专业知识。因此，许多 LLM 预训练数据集使用 Common Crawl [23] 的文本构建。Common Crawl 是自 2007 年开始运行、公开可用且持续更新的网站快照集合。截至本文撰写时，Common Crawl 已生成 100 个网页快照，数据总量达到 PB 级。

尽管 Common Crawl 提供的数据远超训练近期 LLM 所需的数量，但已有研究表明，LLM 的性能可能在很大程度上取决于网页文本在用于预训练之前如何被过滤和预处理 [19]。尤其是，网页文本可能包含大量“非自然”语言，例如“模板化”文本、乱码等。在非自然语言数据上训练可能损害 LLM 性能，原因可能在于 LLM 的大多数下游应用并不涉及此类数据。另一方面，过滤过多内容可能使数据集过小，无法为通用模型提供充分的预训练；预训练通常只对数据集遍历一遍或几遍 [24]。此外，网页文本可能包含大量重复内容，而这也被证明对预训练不利 [5]。尽管去重看似只是“移除重复文本”这么简单，实践中仍需作出许多设计选择：按行、段落还是文档去重？使用模糊匹配还是精确匹配？等等。因此，不同网页文本预训练数据集的整理及相对性能，在很大程度上取决于其过滤与去重流水线。

3 构建 FineWeb

FineWeb 的设计主要基于实证：我们进行了一系列“数据消融”实验，以测试流水线各阶段的不同方法。本节按顺序介绍实验结果和设计选择。除非明确说明，所有消融实验均遵循迭代式数据集构建流程，即各小节的基线模型仅包含此前小节的处理步骤。使用 datatrove 仓库中的代码可以完整复现我们的结果。

3.1 实验设置

为比较各阶段的流水线设计选择，我们训练了除训练数据外完全相同的数据消融模型：参数数量和架构超参数相同，并在各版本数据中随机采样的等量 token 上训练。随后，我们在同一组下游任务基准数据集（下文讨论）上评估模型。为尽可能降低随机选择数据子集对评估分数的影响，我们为每个数据集版本训练两个模型：分别使用完整数据中不同但等大的随机子集，以及不同的初始化种子，然后比较平均分数。

所有训练均使用 nanotron 库。数据消融模型均有 17.1 亿参数（包括 embedding），使用 Llama 架构 [2]，序列长度为 2048，全局 batch 大小约为 200 万 token，使用 GPT2 tokenizer [20]。同一个实验中的所有模型均在相同数量的数据上训练相同步数。过滤消融实验使用约 280 亿 token（大致对应此模型规模的 Chinchilla 最优训练量 [1]）；部分去重消融实验，以及用于确认每一步过滤后累积相对性能提升的实验，使用 3500 亿 token。完整训练超参数见附录 D。消融实验训练的所有模型均在数据集仓库中公开。我们在内部集群上共训练了 70 多个模型，总计约使用 80,000 H100 GPU 小时。

3.2 文本提取

Common Crawl 数据有两种格式：WARC 和 WET。WARC（Web ARChive 格式）文件包含抓取的原始数据，包括完整页面 HTML 和请求元数据。WET（WARC Encapsulated Text）文件使用 htmlparser [48] 提供抓取网站的纯文本版本。虽然 WET 文件通常被用作创建数据集的起点，但与 Gao 等人 [29] 类似，我们发现 WET 文件保留了过多模板化文本和菜单文本。因此，我们尝试使用开源 trafilatura 库 [49] 从 WARC 文件提取文本内容；通过目视检查结果发现，与其他可用库相比，它能提供较好的提取质量，模板化文本和菜单文本较少。定制文本提取的成本相对较高，但其作用体现在模型性能上：图 1 展示了消融模型分别在对 WARC 数据应用 trafilatura 后得到的文本，以及 WET 数据上训练的性能。实验只施加了最少的额外过滤，即使用 fastText 语言识别保留英语为概率最高标签的样本，没有去重。使用 trafilatura 从 WARC 文件提取的文本显然能训练出性能更好的模型，因此后续所有实验均使用基于 WARC 的数据。

3.3 基础过滤

作为过滤的起点，我们使用 RefinedWeb [50] 的部分设置，应用基础过滤流水线。具体而言，我们使用屏蔽列表 [51] 进行 URL 过滤以移除成人内容，应用 fastText 语言分类器 [52, 26] 仅保留分数 \(\ge 0.65\) 的英语文本，并使用 MassiveText [41] 的质量与重复过滤器，沿用原始阈值。对撰写时可用的全部 96 个快照中提取的 WARC 文本应用这些过滤步骤后，使用 GPT-2 tokenizer 得到约 36 万亿 token 的数据。如图 2 所示，这些步骤带来了性能提升。

3.4 去重

网络上有许多聚合网站、镜像、模板化页面，以及分散在不同域名和网页中的其他重复内容。移除这些重复内容（去重）与模型性能提升 [5] 和预训练数据记忆减少 [53, 54] 相关。识别乃至定义重复数据的方法有很多。常见方法依赖哈希技术，或后缀数组等高效数据结构 [55]。方法还可分为通过相似度指标进行的“模糊”去重，以及检查两个文本片段是否完全匹配的“精确”去重 [56]。

遵循 RefinedWeb [50]，我们试验了 MinHash：一种基于哈希的模糊去重技术，能够高效扩展到多个 CPU 节点，并允许通过控制桶数和每桶哈希数调节相似度阈值，以及通过控制 n-gram 大小调节所考虑的子序列长度。我们使用英语词 tokenizer [57] 收集每个文档的 5-gram，使用总计 112 个哈希函数计算 MinHash，并将其分成 14 个桶、每桶 8 个哈希，目标是识别至少有 75% 相似度的文档。在任意桶内具有相同 8 个 MinHash 的文档被视为彼此重复。随后执行传递性聚类：若 A 与 C 重复，B 与 C 重复，那么文档 A、B、C 将被分入同一个重复簇，即使 A 与 B 在任何桶中都没有相同的 8 个 MinHash。每个重复簇随机保留一个文档，其余重复文档被移除。附录 E.1 进一步讨论去重参数。

我们的第一种方法是对整个数据集（全部 96 个快照）执行全局 MinHash 去重。我们以迭代方式实施：从最新快照开始（实验执行时为 2023-50），按时间向过去推进，直到最旧快照。应用于最旧快照时，这个过程移除了多达 90% 的原始基础过滤数据，因为它们要与大量其他快照去重。以此方式对整个数据集去重后，得到 4 万亿 token。然而，在随机采样的 3500 亿 token 子集上训练时，我们的消融模型相比未去重数据上训练的模型几乎没有提升；如图 3 所示，在任务汇总指标上的分数远低于 RefinedWeb。

这挑战了我们最初的假设，即全局去重必然带来更高的基准分数。因此，我们进行了额外实验来研究剩余数据的质量。我们在较早的 2013-48 快照的两个切片上训练两个模型：（a）完全去重后剩余的约 310 亿 token，即原先保留的数据；（b）从迭代去重过程中从该快照移除的约 4600 亿 token 中，通过单独去重、不考虑其他抓取快照，得到的 1710 亿 token，即原先移除的数据。结果见图 4。它们表明，单独考虑这个较早的抓取快照时，保留的数据（原始数据的 10%）质量实际上比移除的 90% 数据更差。目视检查证实了这一点：与原先移除的数据相比，原先保留的数据包含更多广告、不连贯的关键词列表，以及总体上排版更差的文本。

3.5 加入 C4 的过滤器

至此，通过基础过滤和独立 MinHash 去重，我们已达到与 RefinedWeb [50] 相同的性能。然而，我们注意到，C4 数据集 [15] 虽然小于 FineWeb，在评估套件中的部分基准上仍表现更强，尤其是 HellaSwag [43]，它是任务汇总组中信噪比最高的基准之一。尽管 C4 是最早的大规模 LLM 训练数据集之一，它仍经常被用于 Llama 1 [2] 等近期模型的预训练数据混合。我们开始探索能够达到或超越 C4 性能的额外过滤步骤。一个自然的起点是研究 C4 自身的处理过程。

C4 是对 2019-18 抓取快照应用启发式过滤器构建的，过滤器包括：丢弃不以句末标点结尾、提及 javascript 或含有“使用条款”/“cookie 政策”声明的行，以及丢弃过短或包含“lorem ipsum”或花括号（{）的文档。我们尝试将这些过滤器应用于经过基础过滤和单独去重的 2019-18 抓取快照基线，并额外将结果与 C4 本身比较。

图 6 显示，应用所有过滤器（All filters）使我们达到 C4 的 HellaSwag 性能；花括号过滤器（Curly bracket filter）和词长过滤器（Word lengths filter）仅带来小幅提升，分别移除 2.8% 和 4.3% 的 token；句末标点过滤器（Terminal punctuation filter）单独使用时带来的提升最大，但移除了约 30% 的全部 token；lorem_ipsum、javascript 和 policy 规则各自移除的训练 token 均少于 0.5%，因此我们没有分别针对它们训练模型；除句末标点以外的所有过滤器（All but terminal punct）比单独使用 terminal_punct 表现更好，同时移除的总量更少（约 7%）。我们决定应用上述所有 C4 过滤器，但不使用句末标点过滤器，因为它移除了过多数据。

3.6 开发额外的启发式过滤器

以往工作主要通过检查数据来开发启发式过滤器 [15]。在这项工作中，我们设计了更系统的流程，用于设计启发式过滤器并调节阈值。首先，我们在高质量和低质量网页数据集上收集 50 多项高层统计量，范围从文档级指标（如行数、平均行长/词长等）到文档间重复指标（受 MassiveText [1] 启发）。具体而言，我们分别使用 2013-48 快照的单独去重版本和全局去重版本（此前在第 3.4 节提及）作为“高质量”与“低质量”数据集。随后，我们找出在两个数据集间数值分布差异显著的指标，检查两种分布的直方图，并根据经验选择阈值，使过滤针对直方图中低质量数据集频率高于对应高质量数据集的区段。例如，图 8 展示了“以标点结尾的行所占比例”这一指标的分布。可以看到，总体而言，高质量数据集在指标值较大的区域具有更高的文档密度；尤其在数值 < 0.12 时，低质量数据集的文档密度高得多。因此，我们认为以标点结尾的行比例 < 0.12 的文档通常质量较低，并使用该值作为过滤文档的暂定阈值。对所有指标执行这一流程，得到 16 个候选指标与阈值组合。

4 FineWeb-Edu

最近出现了一种有趣的 LLM 训练数据集过滤方法：使用合成数据开发识别教育内容的分类器。这项技术尤其被用于 Llama 3 [6] 和 Phi-3 [8] 未公开的预训练数据集，但它对网页数据过滤的大规模影响尚未得到公开探索。我们将这一技术应用于 FineWeb，使用基于 Llama-3-70B-Instruct [62] 生成的合成标注开发的教育质量分类器进行过滤。所得 FineWeb-Edu 数据集包含 1.3 万亿 token。FineWeb-Edu 专门针对教育内容优化，在 MMLU、ARC 和 OpenBookQA 等多个推理与知识密集型基准上，显著优于所有开放可访问的基于网页的数据集。

为构建合成标注，我们使用 Llama-3-70B-Instruct，对从 FineWeb 的 CC-MAIN-2024-10 快照随机采样的 460,000 个网页，按 0 到 5 分评价教育质量。我们探索了多种提示词格式，以使用 LLM 自动提取教育评分，发现既有工作 Yuan 等人 [63] 使用的累加评分尺度效果最佳。它允许 LLM 评估每项标准并逐步构建分数，而单一评级尺度 [64] 则根据预定义类别直接赋予固定分数。为避免 LLM 偏好 arXiv 摘要和投稿等高度技术性的页面，我们在提示词中要求它聚焦小学和初中水平的知识。合成标注使用的提示词见附录 F.1。

为将过滤扩展至整个 FineWeb，我们在 Snowflake-arctic-embed-m embedding 模型 [65] 之上训练了线性回归模型。我们使用 410,000 条 Llama 3 合成标注，以 3e-4 学习率对该线性回归器训练 20 个 epoch，同时冻结 embedding 层和编码器层。我们将 Llama 3 标注作为真实标签，在包含剩余 50,000 个样本的留出验证集上，选择 F1 分数最高的 checkpoint。训练后，我们将模型输出分数四舍五入为 0 到 5 的整数。随后使用固定阈值判断 FineWeb 中给定文档是否具有教育价值。我们研究了不同过滤阈值的影响，最终为 FineWeb-Edu 选择最低阈值 3，在知识与推理密集型基准的性能和 HellaSwag [66] 等其他基准的性能之间取得最佳权衡。阈值为 3 时，模型在验证集上达到 82% 的 F1 分数，表明它能有效区分高质量教育内容。

5 偏差分析

众所周知，语言模型会反映预训练数据集中的偏差 [72–77]。为简要展示 FineWeb 与 FineWeb-Edu 中的数据集偏差，我们关注在英语国家被认定为“敏感”或“受保护”的子群体。这些群体是历史上受到歧视的群体的一部分，并不成比例地成为刻板印象等负面社会规范的对象；这些现象也反映在数据集所收录的文本语言中。我们发现 FineWeb 数据集中，反映主导性规范的词语相对过度出现，而这些词语已知在网络文本中也过度出现 [72]，例如 ‘man’ 和 ‘christian’。虽然所检查的性别、宗教和年龄子群体间偏差不强，但宗教词语与亲密关系之间的关联最为偏斜，例如 ‘christian dating’ 和 ‘jewish singles’。相应地，与 FineWeb 相比，FineWeb-Edu 捕捉到的关联与亲密关系联系较少，更符合历史和健康类教育内容的预期，例如 ‘man’ 与 ‘king’ 相关，‘woman’ 与 ‘pregnancy’ 相关。更多细节见附录 G。

6 结论

本文开发了 FineWeb 数据集，这是一组能够训练出高性能 LLM 的大规模 LLM 预训练数据集。具体而言，我们发布了 FineWeb：一个从 96 个 Common Crawl 快照获取、包含 15 万亿 token 的数据集；以及 FineWeb-Edu：FineWeb 中包含 1.3 万亿 token 的教育内容数据集。FineWeb 的创建经过一系列实验，为文本提取策略、去重流程和内容过滤器的选择提供了实证依据。两个数据集均已公开发布，同时发布的还有我们使用的代码和处理库，以及在数据集消融实验中训练的所有模型。

虽然 FineWeb 和 FineWeb-Edu 在公开 LLM 预训练数据集中取得了最先进的性能，我们仍识别出多条进一步改进路径。首先，两个数据集完全由 Common Crawl 抓取的网页内容构成。向任一数据集加入其他数据类型（书籍、语音转录等），可能进一步提升性能。此外，由于计算资源限制，我们的大多数实验规模较小。在更现实的规模下设计数据集，可能提供更可靠的指导。我们的评估设置也受实际条件所限，仅考察学术基准上的性能，没有进行后续指令微调或对齐。更贴近 LLM 当前使用方式的评估设置可能也更可靠。我们希望所发布的数据集、代码和模型有助于进一步提升关于高性能 LLM 预训练数据集的公共知识，并推进其开发。

数据字段：

  • text（string）：主要文本内容。
  • id（string）：此样本在 CommonCrawl 中的原始唯一标识符。
  • dump（string）：此样本所属的 CommonCrawl 抓取 batch/快照。
  • url（string）：文本所在原始页面的 URL。
  • date（string）：抓取日期，来自 CommonCrawl。
  • file_path（string）：包含此样本的单个 CommonCrawl WARC 文件的 S3 路径。
  • language（string）：本数据集中所有样本均为 en。
  • language_score（float）：fastText 语言分类器报告的语言预测分数（0.0–1.0）。
  • token_count（int）：对该样本应用 gpt2 tokenizer 得到的 token 数量。

数据划分：默认子集包括整个数据集。我们还为每个 CommonCrawl 抓取 batch 提供单独划分。另有针对教育内容过滤的子集 FineWeb-Edu。

数据集创建

整理理由：通过 FineWeb，我们希望为开源社区提供一个清洁的大规模数据集，用于预训练高性能 LLM。

源数据：源数据由 CommonCrawl 基金会在 2013–2024 年间抓取的网页组成。随后，我们从各网页的 HTML 中提取主要页面文本，过滤每个样本，并对每个 CommonCrawl 抓取 batch/快照分别去重。

数据处理步骤：数据处理流水线包括：

  • URL 过滤。
  • Trafilatura 文本提取。
  • FastText 语言过滤器。
  • MassiveText 重复与质量过滤器。
  • C4 质量过滤器。
  • FineWeb 定制过滤器。
  • MinHash 去重。
  • PII 格式调整。

对于 FineWeb-Edu，我们还应用基于教育内容分类器的过滤步骤。

数据使用注意事项

数据集的社会影响：通过发布 FineWeb，我们希望用以下方式让机器学习社区更容易开展 LLM 训练：

（a）分享包括所用代码库在内的完整处理设置，使数据集创建过程更加透明。

（b）向社区公开发布数据集，帮助模型创建者减轻数据集整理的时间与计算成本。

偏差：我们通过 URL 级过滤，努力减少数据集中 NSFW 和有毒内容的数量。然而，最终数据集仍包含大量可能被认为有毒或含有有害内容的文档。由于 FineWeb 来源于整个网络，网络中常见的任何有害偏差也可能在数据集中再现。对敏感子群体的偏差分析显示，‘man’ 在数据集中比其他性别词语更常见，‘christian’ 比其他宗教词语更常见。特定词语与敏感子群体之间不成比例的关联相对较低，最显著的偏差是部分宗教词语更倾向于与网络约会词语相关。我们在第 5 节提供了更详细的偏差分析。

其他已知限制：由于应用了部分过滤步骤，我们的数据集可能不包含大量代码内容。建议用户考虑用其他代码数据集，以及 Wikipedia 等专门整理的数据来源补充 FineWeb；这些来源的格式可能比 FineWeb 中的 Wikipedia 内容更好。

E.1 去重参数

如第 3.4 节所述，我们使用 5-gram 和 112 个哈希函数进行 MinHash 去重。每个 5-gram 都由全部 112 个哈希函数分别计算哈希，对每个哈希函数取所有 5-gram 中的 MinHash 值（minhash），从而得到文档签名。我们进一步将所得 112 个 minhash 分为 14 个桶，每桶 8 个哈希。如果文档在 14 个桶中的至少一个桶内具有相同的 8 个 minhash，就被判定为匹配。

采用这些参数时，n-gram 相似度（\(s\)）为 0.7、0.75、0.8 和 0.85 的两个文档被识别为重复的概率分别为 56%、77%、92% 和 98.8%。因此，这种划分会以较高概率匹配至少有 75% 相似度的文档，并几乎保证相似度为 85% 或以上的文档能够匹配。这些数值可通过以下概率计算：两个文档在某个哈希函数上具有相同值的概率为 \(s\)；在一个桶中没有相同的 8 个 minhash 的概率为 \(1-s^8\)；在全部 14 个桶中都没有相同的 8 个 minhash 的概率为 \((1-s^8)^{14}\)；最后，在至少一个桶中具有相同的 8 个 minhash 的概率为 \(1-(1-s^8)^{14}\)。

E.3 其他全局去重方法

为尝试在每个快照独立去重的基础上提升性能，我们试验了对所有已分别进行 MinHash 去重的快照（包含 20 万亿 token）应用其他“更轻量”的全局去重方法。

我们探索了 URL 去重：每个规范化为小写的 URL 仅保留一个文档（移除 71.5% 的 token，剩余 5.6 万亿），称为 FineWeb URL dedup。我们还考虑了不同的行级去重变体：每个重复行随机保留一次出现，其他全部移除（丢弃 77.8% 的 token，剩余 4.4 万亿），称为 FineWeb line dedup；与上一个方法相同，但只移除至少有 10 个词的重复行，并丢弃去重后少于 3 个句子的文档（丢弃 85% 的 token，剩余 2.9 万亿），称为 FineWeb line dedup w/ min words；以及每段连续 3 行重复文本仅保留一次出现，在查找重复时将所有数字视为 0（移除 80.9% 的 token，剩余 3.7 万亿），称为 FineWeb 3-line dedup。

G.2 关联分析

接下来，我们使用 TF-IDF [78] 衡量不同子群体词语的偏斜。这一方法被描述为能够捕捉数据集中词语的特异性，此处将其应用于词语相对于不同子群体词语的特异性。这提供了一种方法，用于量化各子群体词语相对于与其共现词语的“偏差”程度。具体而言，给定数据集和所关注子群体的词语，我们：

  1. 构建包含数据集中所有至少出现两次的词语的词汇表。
  2. 提取出现该子群体词语的所有数据实例。
  3. 对词汇表中与给定子群体词语出现在同一文档的所有词语，计算 TF-IDF。
  4. 计算给定子群体词语的 TF-IDF 与其共现的所有其他词语平均 TF-IDF 之间的差异。
  5. 提取与给定子群体词语共现且 TF-IDF 大于 0 的词语。
