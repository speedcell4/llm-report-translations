1. 先确认你的 GPU 与目标

普通 FP8 可以跨两代受支持硬件使用，但 Hopper 普通 FP8 与 Blackwell 原生 MXFP8/NVFP4 要分开比较。Blackwell 数据中心卡增加了微块缩放相关原生路径，框架、CUDA、算子与布局仍决定能否使用。普通 FP8、DeepSeek 风格 block FP8、MXFP8 是三种不同配方；换卡后的最佳选择与加速比需要重测。H20、GB10、RTX Blackwell 也不能套用 B200 的支持结论。先运行 nvidia-smi，并用 PyTorch 查询 torch.cuda.get_device_capability()。查看硬件差异、性能数据与支持边界。

2. 选一条最短上手路线

  • 先跑通服务：使用 vLLM 加载官方量化 checkpoint，先保持 KV 默认精度；确认结果后单独尝试 FP8 KV。安装、服务与请求示例。
  • 自己量化模型：使用 LLM Compressor 生成 vLLM 可加载的压缩 checkpoint。动态 FP8 RTN 可不需要校准数据，AWQ/GPTQ、静态激活和 KV scale 通常需要对应校准。量化脚本与产物检查。
  • 尝试训练：先做 BF16 基线，再用 Transformer Engine 替换受支持的 Linear；不要直接把整个模型转换成 float8。训练示例 · 验证与监控。
  • 消费卡或 CPU 本地运行：先看 llama.cpp/GGUF 或 weight-only；QLoRA 用于冻结量化底座后训练 adapter，与全参数 FP4 训练不同。工具地图。

3. 第一个可复现实验

以 Linux NVIDIA CUDA 环境及正文记录的 vLLM 参考版本为前提，在独立虚拟环境安装后，先启动官方 FP8 权重：

vllm serve Qwen/Qwen3-8B-FP8 \
  --max-model-len 4096 \
  --gpu-memory-utilization 0.85

这条命令只选择 checkpoint；它没有主动把 KV cache 改成 FP8。显存不足时先缩短上下文，具体硬件支持、依赖安装和 API 请求见完整实操。示例经过文档/API核对，未在 GPU 上实跑，不代表任意卡与版本均可运行。

固定模型、prompt、输入/输出长度和并发，分别比较 BF16 与 FP8，再只改变 KV dtype。记录质量、TTFT、TPOT、吞吐量、峰值显存和可承载 token 数；单独报告 prefill 与 decoding。查看基准方法。
