一　官方博客与版本更新

结论

此次未找到 Qwen3.5、Qwen3.6、Qwen3.7 主系列的统一官方技术报告。3.5、3.7 博客仍提到 upcoming technical report；这表示公开材料有缺口，不证明报告绝对不存在。各版本仍有具体技术披露，不能理解为只有模型名和榜单变化。

主系列逐项变化

Qwen3.5：原生多模态、混合 Attention 与训练系统

来源：官方发布博客。

  • 以文本、图像联合早期融合实现原生视觉语言预训练，增加视觉文本、多语言及 STEM 数据并强调过滤；未给出可完整复现的数据比例和训练配方。
  • 397B 总参数、17B 激活的旗舰，继承 Qwen3-Next 的 Gated DeltaNet / Gated Attention 混合结构与高稀疏 MoE，并使用 MTP。
  • 语言和方言覆盖由119增至201，词表由约150K扩至约250K；配置中的填充词表数不能直接当作自然语言词数。
  • 异构多模态并行、视觉与语言组件计算重叠；原生 FP8 训练同时在敏感位置保留 BF16。
  • 异步 RL 将训练、推理解耦，并使用 rollout router replay、speculative decoding、多轮 rollout 锁定等控制陈旧数据与吞吐。博客的加速数字对应官方系统，不能直接外推到用户机器。
  • 强调扩展 RL 环境的任务质量、难度与泛化，但更多方法和分析仍指向待发布报告。
  • 托管 Qwen3.5-Plus 的默认1M上下文和内置工具是服务规格，不能直接套到所有开放权重。

Qwen3.6：工程 Agent 与历史思考保留

来源：Plus 博客、35B-A3B 博客、35B 官方模型卡、27B 博客。

  • Plus 是托管版本，发布重点是实际工程编码和多模态任务，默认1M上下文；未公开其完整参数规模、架构与训练配方。
  • 开放权重包括35B-A3B MoE 和27B dense模型，均支持图像/视频及 thinking/non-thinking。35B的API产品名称为Qwen3.6-Flash。
  • 对照对应3.5与3.6官方配置：35B均为40层、hidden size2048、256 experts；27B均为64层、hidden size5120。两组对应模型的 vision_config 完全相同，原生 max_position_embeddings 均为262144。
  • 配置并非逐字相同：BOS、tie_word_embeddings 等显式字段不同；27B新增 output_gate_type='swish'。后续源码核查确认：当前 Transformers 不读取 output_gate_type，GatedDeltaNet 原本就固定 SiLU；该字段不能作为新门控结构证据。对应开放模型复用同一实现，但不能外推所有引擎或内部训练代码。
  • 35B模型卡明确说训练支持利用历史 reasoning。默认保留最近一次用户提问之后的思考，preserve_thinking=true 可保留全部历史思考，减少多轮重复推理、增强连续性，也有利于缓存复用。实际部署需服务和模板正确传回 reasoning_content。
  • 公开材料支持“主体结构延续而能力与交互方式升级”的判断；无法从公开信息精确拆分预训练、后训练、数据与系统各自贡献。

Qwen3.7：跨框架泛化与长时程执行

来源：Qwen3.7: The Agent Frontier。主体介绍闭源Qwen3.7-Max，不能把其他材料中的Plus/Base配置直接当作Max配置。

  • 环境扩展强调质量、多样性以及未见过的环境中的泛化。
  • 将 Task、Harness、Verifier 分离并组合，训练时变化工具框架及其版本与验证方式，目标是避免策略只适应特定框架。
  • Dynamic Cumulative Survival Games用于训练上千步执行时的策略一致性、上下文记忆，以及抵抗上下文衰退与指令漂移。
  • Reward hacking 监测展示了自演化检查工具：约80小时、10K工具调用，产生13条规则并标记1618个案例。这是训练研究案例，不是所有部署的标配。
  • Kernel优化案例运行约35小时、1158次工具调用、432次评估。案例速度收益不能当作普遍基准收益。
  • 未公开Max精确参数、层数、完整数据量和训练超参数；博客仍把更完整scaling方法分析指向后续报告。

同一3.7博客表内，3.6-Plus→3.7-Max：SWE-Pro56.6→60.6，SkillsBench45.7→59.2，MCP-Mark48.2→60.8，MRCR-v2 128K85.9→90.4。比较对象同时更换了Plus/Max档位，不能单独归因于版本号。不同发布博客的评测时限、框架及资源可能变化，尤其Terminal-Bench；不要直接跨博客拼榜。

二　HF Hub 与 Transformers 核查

核查日期：2026-10-10。针对上一轮博客调查，检查官方 Hub 的10个基础精度主系列 checkpoint、2个3.6 FP8 checkpoint，以及当前 Transformers 实现。只下载配置、模板、模型卡和权重索引，没有下载大模型张量或执行推理。

结论：开放的3.6-27B与3.6-35B-A3B复用3.5的计算实现，主体结构配置与对应3.5一致。可直接确认的升级包括模型权重发布、保留历史思考的输入协议、工具参数序列化和部分推理默认值；无法从这些文件还原完整训练方法。 官方Qwen账号的3.7搜索本次为空，当前Transformers没有单独qwen3_7目录；闭源3.7-Max的内部实现仍未公开，不能以3.5/3.6代码替代。

两组3.5→3.6对应模型的vision_config、image/video预处理配置完全一致，非 MTP 的权重键名集合也一致。这证明公开计算结构/参数布局高度延续，不证明权重数值相同，也不揭示新增数据或训练步骤。

上次留下的swish疑点可以收窄了

3.6-27B新增output_gate_type="swish"，但固定版本的六份configuration/modeling/modular文件都不读取该字段。代码实际使用两种不同的门：

  • GatedDeltaNet：RMSNorm后乘SiLU(z)，activation在RMSNormGated中已固定为silu（通常称Swish，beta=1）。
  • Full attention：q_proj同时投影query和gate，attention 输出乘 sigmoid(gate)，再o_proj。

所以不能说“3.5用 sigmoid，3.6改成Swish”：它们是两个不同模块的门，同一代码本来就同时存在。新增字段在此实现中不产生新的运算分支；其他引擎和内部训练代码未检查，不能扩大结论。

另外partial_rotary_factor=.25在3.5的rope_parameters里已经存在，当前配置类也有兼容默认值；3.6新增外层重复字段不表示首次采用partial RoPE。tie_word_embeddings=false在3.5根配置已经存在；3.6再写入text_config不表示首次解除共享。BOS/pad等显式字段变化是输入/生成元数据，不能当作网络层变化；两版generation_config的BOS/EOS/pad ID保持一致。

源码：RMSNormGated L204–220、full attention L735–807、配置兼容默认 L90–119。

preserve_thinking到底做什么

对应27B与35B模板都是同样两处差异。第一处：3.5只在assistant消息位于最近用户提问之后时保留think块；3.6增加preserve_thinking is true条件，可以把更早轮次思考一起放回模型输入。

这不是持久化内存或 Transformer 新增状态；服务必须保留并重新提供历史reasoning_content，或含think标记的content，否则模板不能恢复被丢弃的思考。用户发起下一轮提问后，默认设置会去掉更早轮次思考；同一次提问的工具调用链内，3.5本来就会保留当前轮思考。

enable_thinking=false是生成前缀放入空think块，和“是否保留历史think”是独立设置。不存在源码新增thinking/non-thinking两套独立模型。

3.6模型卡明确另有训练支持历史思考利用，这是训练披露；Jinja差异只证明输入协议，不能单独证明训练方法或性能收益。保留历史可能减少重复推理、提高前缀缓存复用，也会增加输入长度，实际总耗时取决于任务和服务缓存。

模板：3.5-35B、3.6-35B；训练说明：3.6模型卡。

博客容易略过的工具协议修正

模板第二处差异是参数序列化：3.5对mapping/list做JSON，其他值用string；3.6只让字符串原样输出，全部非字符串走JSON。

实际渲染：布尔True由True变true，空值None由None变null；数字保持数字，字典/数组仍用JSON。工具调用整体仍为tool_call/function/parameter标记，并未换成另一套完整协议。这里是兼容性细节，不能声称它单独解释整组工具榜单提升。上述差异已经实际模板渲染验证。

推理默认值、上下文与视频预算

  • 27B的generation_config温度由0.6变1.0；35B仍为1.0。两组的do_sample=true、top_p=.95、top_k=20、EOS列表[248046,248044]一致。调用端显式传参会覆盖默认值。
  • 3.6模型卡并不是建议所有任务温度1.0：通用thinking为1.0，精确编码thinking为0.6，non-thinking为0.7/top_p=.80/presence_penalty=1.5。因此对比版本应控制采样参数，而非只使用各自默认值。
  • 原始配置是262144，rope_type=default。模型卡的约1M是YaRN扩展：factor=4、original_max_position_embeddings=262144，并设置服务最大长度1010000。托管Plus的1M、开放权重原生长度和扩展服务长度是三个不同概念。模型卡提示静态YaRN可能影响短文本效果。
  • image size longest_edge=16777216/shortest_edge=65536；video为25165824/4096。这里是处理器像素预算配置，不是图像单边允许16777216像素。两版相同。
  • 模型卡建议长视频提高video longest_edge到469762048（官方标注约224K video tokens）；不能以默认采帧/预算直接期待长视频评测效果，实际还受fps和上下文预算影响。

来源：3.5-27B generation_config、3.6-27B generation_config、3.6-27B模型卡。

Tokenizer 没有另换一套

四个对应 checkpoint 的 tokenizer.json均为12,807,982字节，Hub LFS SHA256均为5f9e4d4901a92b997e463c1f46055088b6cca5ca61a6522d1b9f64c4bb81cb42。tokenizer_config除内嵌聊天模板之外无差异；词表配置248320、图像/视频特殊 token ID也一致。由官方blob哈希确认文件相同，而非只比较vocab_size。

因此3.6的变化不能解释为新 tokenizer 带来的压缩率提升。这个结论限定上述27B/35B checkpoint，不外推闭源Plus/Max。来源为各模型固定revision的官方Hub文件元数据；仓库版本列于本页来源表。

MTP 确有权重，但支持取决于引擎

四个 checkpoint 配置均为mtp_num_hidden_layers=1、mtp_use_dedicated_embeddings=false；权重索引都有 mtp.*参数。27B两版各15个 MTP 键；35B从785键变19键，原因是3.5的 MTP 专家以256组gate/up/down分别存储，3.6打包成experts.gate_up_proj和experts.down_proj。键数减少不表示减少专家。主干非 MTP 键集合两版相同。

当前Transformers模型代码把^mtp.*作为可忽略的unexpected keys，没有对应 MTP 模块和forward。普通AutoModel加载并generate不能自动获得该 checkpoint 的 MTP 加速。官方模型卡提供vLLM参数--speculative-config '{"method":"qwen3_next_mtp","num_speculative_tokens":2}'，说明引擎层需要明确启用；本次没有审计或运行vLLM实现。MTP 隐藏层数1也不能直接当作一次可预测 token 数上限。

来源：3.5-35B权重索引、3.6-35B权重索引、Transformers忽略 MTP L903–913。

混合 Attention、MoE、位置编码的实际运算

  • GatedDeltaNet：Q/K/V经过kernel4的depthwise因果卷积；Q/K做L2 normalization；sigmoid 控制delta更新强度，softplus/exp控制递归衰减。Q/K与V头数可不同，重复匹配。实现L490–647
  • MoE：FP32 softmax 后 top-k，入选专家概率重归一化；共享专家始终执行，其输出再乘独立 sigmoid 门。35B/122B是8个路由专家+1个共享，397B是10+1；不能简单用总参数乘8/256得到激活参数。实现L871–909
  • 位置编码：head_dim256的25%即64维做旋转；MRoPE [11,11,10]在频率上交错分配时间/高/宽，纯文本三轴相同。不能把重复配置字段解释为新位置编码。实现L135–200
  • 缓存：linear层存卷积/递归状态，full层仍存历史KV。大量层省去了完整KV，并不使整个模型成为常量内存。full KV L779–783

原生多模态不表示取消独立视觉塔

Conv3d将输入按temporal_patch_size2、patch_size16切块；视觉编码器输出由spatial_merge_size2合并相邻2×2特征，经merger映射到语言hidden size，再替换序列里的图像/视频占位 embedding。config中的deepstack_visual_indexes=[]，当前实现没有Qwen3-VL式中间层DeepStack注入。联合训练与统一序列处理不等于取消视觉encoder，也不意味着继承Qwen3-VL的所有机制。

来源：patch/merger L947–980、特征替换 L1601–1645。

FP8发布是量化格式，不是全模型每处都FP8

3.6两款官方FP8 config均为quant_method=fp8、fmt=e4m3、activation_scheme=dynamic、weight_block_size=[128,128]，但同时列出大量modules_to_not_convert，涉及视觉层、norm、路由/共享门、线性 attention 部分和 MTP 部分。不能把“FP8模型”理解为所有权重和运算都FP8，也不能由推理量化配置反推出FP8训练全流程。实际转换哪些模块需结合引擎的名称匹配与实现。

来源：27B-FP8配置、35B-FP8配置，固定revision见extra-manifest。

仍不能确认的部分

未执行模型推理、数值等价测试或性能benchmark；未完整检查vLLM/SGLang和官方内部训练代码。当前Transformers main可能晚于模型发布，不能反推发布日期支持状态。相同结构不能证明3.6仅做 RL 或 SFT，博客和Hub仍不足以还原完整训练数据、阶段与参数。3.7-Max闭源实现无法从当前公开Hub补齐。
